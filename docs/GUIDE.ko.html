Inkling 사용 설명서

초대받아 쓰시는 분을 위한 설명서입니다. 메뉴가 어디 있는지 찾기 쉽게 정리했습니다.

이 문서는 저장소의 docs/GUIDE.ko.md을 그대로 옮겼습니다. Markdown 원문

다른 분이 운영하는 Inkling 서버에 초대받아 쓰시는 분을 위한 문서입니다. 기능 설명보다는 "그 메뉴가 어디 있는지"를 찾기 쉽게 쓰려고 했습니다. 서버를 직접 설치하고 운영하시는 분은 README.ko.md, deploy/DEPLOY.ko.md, OPERATIONS.ko.md를 참고하시기 바랍니다. 영어판은 GUIDE.md입니다.

단축키는 맥(⌘) 기준으로 적었습니다. 윈도우나 리눅스에서는 ⌘ 대신 Ctrl을 누르시면 되고, 둘이 다른 경우는 아래 단축키 표에 따로 적어 두었습니다. 메뉴 이름은 앱 언어를 한국어로 두었을 때 화면에 나오는 이름 그대로입니다.

시작하기

로그인

처음 가입하실 때는 서버 운영자에게 받은 가입 키가 있어야 합니다. 로그인 화면에서 '가입 키로 가입하기'를 누르고 키를 붙여 넣은 다음, 이름과 이메일, 비밀번호(8자 이상)를 입력하시면 됩니다.

비밀번호를 잊으셨다면 로그인 화면의 '비밀번호를 잊었나요?'를 누릅니다. 관리자나 메일로 받은 재설정 코드가 있으면 '코드가 있어요'에 입력하시면 되고, 없으면 '코드가 없어요'에서 요청을 보내시면 됩니다. 서버가 메일을 보낼 수 있으면 재설정 메일이 오고, 그렇지 않으면 관리자가 코드를 따로 전해 드리게 됩니다.

화면 언어는 처음에는 브라우저 언어를 따릅니다. 바꾸시려면 설정 › 모양 › 언어에서 고르시면 됩니다.

서버를 운영하는 사람이 가입 방식을 바꿔 둔 서버도 있습니다(데모 서버 같은 곳). 그런 서버에서는 이메일 주소 대신 '아이디'와 '별명'으로 가입할 수 있습니다(영문 소문자, 숫자, ., _, -로 3~30자). 아이디와 별명에는 실명, 이메일 주소, 전화번호를 넣지 마세요. '가입하기'를 누르기 전에 서버의 고지와 약관에 체크해야 할 수도 있습니다. /terms와 /privacy는 로그인하지 않아도 열리고, 설정에서도 들어갈 수 있습니다. 모든 화면에 "데모" 같은 표시가 보일 수도 있습니다.

약관이 바뀌면 로그인한 뒤 다른 화면보다 먼저 '계속하려면 약관에 동의하세요'가 나옵니다. 약관을 읽고 '동의하고 계속하기'를 누르거나, '동의하지 않고 로그아웃'을 누르시면 됩니다. 같은 화면에 '계정 삭제'도 있습니다.

가입하고 며칠 뒤 계정을 지우는 서버에서는 사이드바 맨 위의 워크스페이스 이름 아래에 "이 계정은 YYYY-MM-DD에 삭제됩니다."가 '내보내기' 링크와 함께 나옵니다(휴대폰에서는 페이지 위에, 마지막 3일 동안은 모든 화면에). 남기고 싶은 것은 그날 전에 내보내 두세요.

소개와 시작하기 카드

새 계정으로 처음 들어오면 짧은 소개가 나옵니다. 함께 쓰는 노트, 질문에 필요한 대목만 찾아 읽는 AI 에이전트, 에이전트가 고친 것을 사람이 받아들이는 모습, 내 서버와 오프라인 복사본을 차례로 보여 줍니다. Esc나 '건너뛰기' 버튼으로 넘길 수 있고, ←·→로 장면을 옮기고 Space로 멈춥니다. 끝나면 닫히지 않고 다음에 할 일을 고르는 화면에서 멈춥니다. 샘플 페이지 열기(또는 만들기), '새 페이지 만들기', 'AI 에이전트 연결', '닫기'가 있습니다. 시스템에서 '동작 줄이기'를 켜 두셨다면 장면마다 멈춘 그림으로 보여 주고, 마지막 그림 다음에 같은 화면이 나옵니다.

빈 워크스페이스 화면과 사이드바 아래쪽(접힌 채로)에 '시작하기' 카드가 있습니다. 처음 해 볼 일이 적혀 있고, 해 보면 저절로 체크됩니다. 체크는 기기마다 따로 남지 않고 계정에 남습니다. 항목을 누르면 그 일을 하는 곳으로 가서 어디를 누르면 되는지 작은 말풍선으로 알려 줍니다. '연습용 샘플 페이지 만들기'를 누르면 내 개인 페이지에 연습용 페이지가 생깁니다(나만 봅니다). 다 보고 나서 지워도 되고, 지운 샘플은 다시 생기지 않습니다. 카드가 필요 없으면 '다시 보지 않기'를 누르세요. 사이드바에서 카드를 펼치면 메뉴와 페이지 트리가 쓰고 남은 높이만큼만 커지고, 목록이 더 길면 카드 안에서 스크롤됩니다. 창이 낮은데 '더보기'까지 펼쳐 둬서 그만한 자리도 없으면 자리가 날 때까지 접힌 채로 있습니다.

설정 › 정보 › 시작하기에서 '소개 다시 보기'를 누르거나 체크리스트를 다시 켤 수 있습니다. 업그레이드 전부터 있던 계정은 체크리스트가 꺼진 채로 시작하고, 소개는 서버 운영자가 ONBOARDING_EXISTING_USERS=once를 넣었을 때만 한 번 나옵니다. 글을 쓰고 있을 때는 소개가 끼어들지 않습니다.

워크스페이스

워크스페이스는 팀이 함께 쓰는 공간입니다. 처음 로그인하면 '새 워크스페이스 만들기'와 '초대 코드로 참여' 중 하나를 고르게 됩니다. 초대 링크(…/join/<코드>)를 받으셨다면 로그인한 상태에서 링크를 열고 '참여'를 누르시면 됩니다.

사이드바 맨 위에 있는 워크스페이스 이름을 누르면 워크스페이스 메뉴가 열립니다. 여기서 다른 워크스페이스로 옮겨 가거나, 멤버 관리, 워크스페이스 설정, 새 워크스페이스, 코드로 참여, 가져오기와 내보내기를 할 수 있습니다.

페이지 트리는 공유와 개인 두 구역으로 나뉘어 있습니다. 공유 구역의 페이지는 워크스페이스 멤버 모두가 읽고 고칠 수 있고, 개인 구역(자물쇠 표시)의 페이지는 본인만 볼 수 있습니다. 개인 페이지는 웹에 공유하거나 편집 잠금을 걸 수 없습니다. 페이지를 다른 구역으로 옮기시려면 오른쪽 패널의 속성에서 '개인으로 전환' 또는 '공유로 전환'을 누르시면 됩니다.

역할은 소유자, 관리자, 멤버 세 가지가 있습니다. 워크스페이스 설정은 소유자가 바꾸고, 웹 공개와 편집 잠금은 소유자와 관리자가 맡습니다.

워크스페이스 설정 › 일반의 '사용량'에는 워크스페이스의 멤버 수, 페이지 수(휴지통 포함), 저장 용량(파일, 페이지 본문, 버전 히스토리, 필기, 코멘트, 휴지통)이 나옵니다. 한도가 있는 서버에서는 '한도 중 사용량'으로 보입니다. 한도를 넘겨 만들려고 하면(페이지, 멤버, 내가 소유한 워크스페이스, 파일 하나의 크기) 어느 한도인지 알려 주는 안내가 나옵니다. 삭제한 워크스페이스도 완전히 지워지기 전까지는 내가 소유한 워크스페이스 수에 들어갑니다. 저장 용량이 차면 워크스페이스는 모두에게 읽기 전용이 되고 페이지 위에 안내가 나옵니다. 파일이나 페이지를 지우고 휴지통을 비운 다음 사용량을 다시 열어 보세요. 서버가 다시 세어 한도 아래로 확인하면 열려 있던 페이지도 다시 고칠 수 있습니다.

워크스페이스가 많아져서 메뉴가 길어지면 묶음과 보관을 쓰시면 됩니다. 워크스페이스 메뉴에서 '워크스페이스 정리…'를 누르고 "대회", "수업" 같은 묶음을 만든 다음, 워크스페이스마다 묶음을 고르고 끌거나 화살표로 순서를 바꿉니다. 끝난 워크스페이스는 보관해 두면 메뉴 맨 아래 '보관됨'으로 내려갑니다. 여전히 한 번에 열 수 있고 고칠 수도 있지만, 모든 워크스페이스를 한꺼번에 찾는 검색(AI 에이전트의 기본 검색도 포함)에서는 빠집니다. 이건 내 목록에만 적용되는 정리라서 다른 멤버에게는 아무것도 바뀌지 않습니다. 되돌리려면 '보관 해제'를 누르시면 되고, 같은 화면이 설정 › 사이드바에도 있습니다.

페이지 만들기

새 페이지는 사이드바 위쪽의 '새 페이지'나 ⌘N으로 만듭니다. 바로 옆의 작은 화살표(˅)를 누르면 새 문서, 새 폴더, 새 데이터베이스, 새 캔버스, 템플릿에서 시작 중에서 종류를 고를 수 있습니다. ⌘N으로 만든 페이지가 최상위에 생길지, 지금 페이지 안이나 옆에 생길지는 설정 › 파일 · 링크 › 새 페이지 위치에서 정하시면 됩니다.

트리에서 페이지 위에 마우스를 올리면 + 버튼(하위 페이지 추가)과 ⋯ 메뉴가 나옵니다. ⋯ 메뉴는 우클릭으로도 열리고, 하위 페이지나 하위 폴더, 하위 데이터베이스를 만들거나 이동…, 복제, 이름 바꾸기, 즐겨찾기에 추가, 템플릿으로 저장 같은 일을 여기서 합니다. 페이지 순서를 바꾸거나 다른 페이지 안으로 넣고 싶을 때는 트리에서 끌어다 놓으시면 됩니다.

사이드바의 '오늘'을 누르면 오늘 날짜의 데일리 노트가 열립니다. 어제나 내일 노트는 명령 팔레트(⌘P)에서 열 수 있습니다.

찾기

⌘K는 검색으로, 제목과 본문을 함께 찾습니다. 제목만 알고 빨리 넘어가고 싶을 때는 ⌘O(빠른 전환)가 편합니다. ⌘P는 명령 팔레트인데, 페이지 이동 말고도 새 페이지 만들기, 휴지통 열기, 테마 바꾸기, 워크스페이스 바꾸기 같은 명령을 여기서 실행할 수 있습니다. 자주 여는 페이지는 페이지 머리글의 별(☆)을 눌러 즐겨찾기에 넣어 두시면 트리 위쪽에 따로 모입니다.

글쓰기

슬래시 메뉴와 블록

문서에서 /를 치면 블록을 고르는 메뉴가 뜹니다. 제목, 목록, 체크리스트, 토글 목록, 인용, 표, 코드 블록, 이미지와 파일 같은 기본 블록이 있고, Inkling에서 따로 넣은 블록도 몇 가지 있습니다.

콜아웃은 눈에 띄게 강조하는 상자입니다. 블록 안의 아이콘을 누르면 노트, 팁, 경고, 위험, 정보 중에서 종류를 바꿀 수 있습니다. 임베드 / 링크 카드는 YouTube, Figma, Google Docs 같은 링크를 붙여 넣으면 페이지 안에 띄워 주는 블록이고, 임베드와 미리보기 카드, 일반 링크 중에서 보이는 방식을 고를 수 있습니다. 수식 블록과 인라인 수식, 쿼리는 아래에서 따로 설명하겠습니다. 차트 블록은 데이터베이스 쪽의 차트에서 설명합니다. '데이터베이스 보기' 블록은 데이터베이스에 적어 두었습니다.

표는 바로 쳐서 만들 수도 있습니다. 빈 줄에 | 이름 | 역할 | 마감 |처럼 세로줄로 칸을 나눠 쓰고 Enter를 누르면, 그 줄이 머리글 행이 되고 아래에 빈 행이 하나 붙은 표로 바뀝니다. 바로 ⌘Z를 누르면 다시 글자로 돌아갑니다. 칸 안에 세로줄을 넣고 싶으면 \|로 쓰시면 됩니다. 크기를 정해서 넣고 싶을 때는 /표 3x4처럼 치시면 3열 4행짜리 빈 표가 들어갑니다(/table 3x4, 3*4도 됩니다). 마크다운 표를 복사해서 붙여 넣어도 표가 됩니다.

이미지와 파일은 페이지에 끌어다 놓기만 해도 들어갑니다. 맨 위의 큰 글씨가 제목이고, F2를 누르면 제목으로 바로 갑니다.

단 나누기

빈 줄에서 /2단이나 /3단을 입력하면 그 자리가 좌우로 나란한 단으로 바뀌고 커서가 첫 단에 들어갑니다. 단 안에서는 평소처럼 쓰시면 됩니다. 이미지, 할 일, 코드, 콜아웃, 토글 같은 블록도 다 들어갑니다. 방향키로 단 사이를 오가고, Tab·Shift+Tab은 단 안에서 들여쓰기만 합니다. 단 맨 앞에서 Backspace를 누르면 줄을 끌어내지 않고 커서만 왼쪽 단 끝으로 갑니다.

폭은 두 단 사이에 마우스를 올리면 생기는 선을 끌어서 바꿉니다. 그 선을 두 번 누르면 모든 단이 같은 폭이 됩니다. 단 안 블록의 블록 메뉴(블록 옆 ⋮⋮)에 단 추가(4개까지), 이 단 삭제(그 단 내용은 왼쪽 단 끝으로 옮겨짐), 단 풀기(단 순서대로 보통 블록으로 돌아감)가 있습니다. 단 안에 단을 또 넣을 수는 없습니다.

화면이 좁으면 단이 첫 단부터 세로로 쌓입니다. 단 안의 제목은 섹션이 아니라서 목차에 안 나오고, 발표 슬라이드도 거기서 나뉘지 않습니다. 에이전트는 단 묶음을 감싼 섹션 단위로 고칩니다. 단 안의 이미지도 다른 이미지처럼 크게 볼 수 있습니다('이미지 크게 보기' 참고).

수식

한 줄을 따로 차지하는 수식은 / › 수식 블록으로 넣습니다. 문장 안에 넣을 때는 $x^2$처럼 달러 기호로 감싸서 입력하시거나, 글자를 고른 상태에서 ⌘⇧E를 누르시면 됩니다. 수식을 누르면 LaTeX를 고칠 수 있는 창이 열리고, 고치는 동안 결과가 바로 보입니다. $5 and $10처럼 가격을 적은 경우는 수식으로 바뀌지 않도록 해 두었습니다.

다이어그램

코드 블록의 언어를 mermaid(또는 mmd)로 두면 코드 아래에 Mermaid 다이어그램이 그려집니다. 순서도, 시퀀스 다이어그램, 간트 차트처럼 Mermaid가 지원하는 종류는 다 됩니다. 코드를 고치는 동안에는 코드가 보이고, 다이어그램을 누르면 다시 편집할 수 있습니다. 코드를 계속 펼쳐 두고 싶으면 '코드 보기'를 누르시면 됩니다. 코드에 틀린 곳이 있으면 '다이어그램 오류'와 함께 무엇이 틀렸는지 한 줄로 알려 줍니다. 라이트·다크 테마를 따라가고, 발표 모드에서는 다이어그램만 보이며, 'PDF로 내보내기'와 웹에 공개한 페이지에서도 그려집니다. 에이전트나 내보내기, 볼트 동기화에는 ```mermaid 코드 그대로 갑니다.

버튼

/버튼(또는 /button)을 입력하면 버튼이 들어갑니다. 라벨과 색을 정하고 누를 때 할 일을 다섯 개까지 순서대로 넣습니다. 데이터베이스에 '행 추가'(템플릿과 값을 고르고, 값에는 today, today+7, me, this나 글 안의 {{today}}·{{me}}·{{page}}를 쓸 수 있습니다), 이 페이지가 데이터베이스 행일 때 '이 행의 값 바꾸기', 페이지나 링크 '열기', 워크스페이스 소유자가 등록해 둔 '웹훅 보내기'가 있습니다. 버튼은 누른 사람의 권한으로 돌기 때문에, 그 데이터베이스에 행을 넣을 수 없는 사람은 버튼으로도 못 넣습니다. 중간에 실패하면 몇 번째 동작에서 왜 멈췄는지 알려 줍니다. 웹에 공개한 페이지와 발표 모드에서는 버튼이 보이기만 하고 눌리지는 않습니다.

링크, 멘션, 태그

[[를 치면 다른 페이지로 가는 링크를 걸 수 있습니다. 목록에서 페이지를 고르셔도 되고, 아직 없는 페이지라면 '＋ 새 페이지: "…"'를 눌러 그 자리에서 만들 수도 있습니다. ![[로 시작하면 링크 대신 그 페이지의 내용을 그대로 끼워 넣습니다.

[[페이지#까지 치면 그 페이지의 헤딩 목록이 나오고, 하나를 고르면 그 헤딩으로 바로 가는 섹션 링크가 됩니다. 헤딩 이름을 바꾸거나 위치를 옮겨도 링크는 그 헤딩을 따라가고, 헤딩이 지워졌으면 페이지를 연 다음 헤딩을 찾지 못했다고 알려 줍니다. 백링크 패널에는 링크를 건 페이지가 어느 헤딩을 가리키는지도 같이 나옵니다.

@로는 멤버나 페이지를 멘션합니다. 멤버를 멘션하면 그 사람에게 알림이 갑니다. #태그처럼 쓰면 태그가 붙고, 사이드바의 '태그'에서 태그별로 페이지를 모아 볼 수 있습니다. 내부 링크에 마우스를 올리면 그 페이지를 미리 보여 주는데, 이게 거슬리시면 설정 › 파일 · 링크 › 링크 미리보기에서 끄시면 됩니다.

오른쪽 패널

페이지 오른쪽 위의 패널 버튼을 누르면 오른쪽 패널이 열립니다. 속성, 개요, 코멘트, 백링크, 미연결 멘션, 나가는 링크, 태그, 별칭, 로컬 그래프, 버전 히스토리가 이 안에 있습니다. 미연결 멘션은 다른 문서에서 이 페이지 제목을 쓰긴 했는데 아직 링크로 걸리지 않은 곳을 찾아 주는 기능입니다. 속성을 바로 고치고 싶을 때는 ⌘;를 누르시면 됩니다.

긴 문서 읽기

제목이 셋 이상 있는 문서는 창이 넉넉하면 본문 오른쪽 여백에 제목마다 짧은 줄이 그어집니다. 줄에 마우스를 올리면 목차가 펼쳐지고, 제목을 누르면 그 자리로 갑니다. 지금 읽고 있는 곳의 줄은 조금 진하게 보입니다. 거슬리시면 설정 › 편집기 › 오른쪽 목차에서 끌 수 있습니다.

맨 바깥 단계의 제목에 마우스를 올리면 제목 왼쪽에 화살표가 생기는데, 이걸 누르면 다음에 나오는 같은 단계나 더 큰 제목 앞까지 접힙니다. 한 번 더 누르면 다시 펼쳐집니다. 키보드로는 ⌘.(Ctrl+.)을 누르면 커서가 있는 곳이 접히고 펼쳐집니다. 본문 중간에서 누르면 커서가 그 제목 끝으로 옮겨진 다음에 접힙니다. 폰이나 태블릿에서는 제목을 한 번 탭하면 그 줄 끝에 화살표가 나오니 그걸 누르시면 됩니다. 접힌 제목 뒤에는 "…"가 붙고 화살표도 계속 보입니다.

접어 둔 상태는 이 기기에서 페이지별로 기억해 두고 문서 내용은 건드리지 않기 때문에, 다른 사람에게는 펼쳐진 채로 보입니다. 접힌 곳은 커서가 그 안으로 들어갈 때(제목 끝에서 Enter를 누르는 경우 등), 목차나 코멘트, 할 일에서 그 안으로 이동할 때, ⌘F(Ctrl+F)로 브라우저 찾기를 열 때 저절로 펼쳐집니다. ⌘F를 누르면 찾는 말이 있는 곳만이 아니라 그 페이지에서 접어 둔 곳이 전부 펼쳐지는데, 브라우저 찾기는 접힌 글자를 못 보고 무엇을 찾는지도 페이지에 알려 주지 않아서 그렇게 해 두었습니다. 필기 모드와 인쇄에서는 전부 펼친 모양으로 나옵니다. 다른 블록 안에 들여 쓴 제목은 접히지 않습니다.

이미지 크게 보기

페이지에 넣은 사진은 더블클릭하거나, 마우스를 올리면 오른쪽 위에 생기는 돋보기 버튼을 누르면 크게 볼 수 있습니다. 폰이나 태블릿에서는 돋보기가 늘 보입니다. 읽기만 할 수 있는 페이지(나에게 잠긴 페이지)와 공개 링크에서는 사진을 한 번 누르면 열립니다. 공개 링크에서 사진에 링크가 걸려 있으면 그 링크로 갑니다. 편집할 수 있는 페이지에서 한 번 누르는 건 지금처럼 이미지 블록을 고르는 동작이라서, 도구 막대나 크기 조절 손잡이, 끌어서 옮기기는 그대로 쓰시면 됩니다.

크게 본 화면에서는 마우스 휠이나 트랙패드를 오므리고 벌려서, 터치 화면에서는 두 손가락으로 확대·축소합니다. 손가락이나 커서가 있던 자리를 중심으로 커집니다. +, -로 한 단계씩 바꾸고, 0을 누르면 화면에 맞춰지고, 더블클릭하면 화면 맞춤과 원래 크기(100%)가 번갈아 바뀝니다. 화면보다 작은 사진은 처음부터 100%로 나오고 화면에 맞춘다고 더 커지지는 않습니다. 화면보다 크게 키웠을 때는 끌어서 옮겨 볼 수 있습니다. 한 페이지에 사진이 여러 장이면 ←, →나 양옆 화살표로 앞뒤 사진으로 넘어가고, 위쪽 막대에 몇 번째인지("2 / 5"), 캡션이나 파일 이름, 배율, 원본 열기(새 탭에서 열기)가 나옵니다. Esc를 누르거나 사진 바깥을 누르거나 닫기 버튼을 누르면 보던 자리로 돌아갑니다. 브라우저의 뒤로 가기는 평소처럼 이전 화면으로 가면서 크게 보기도 닫습니다. 열려 있는 동안 누르는 키는 뒤에 있는 페이지로 가지 않습니다. ? 창의 이미지 보기 묶음에도 이 키들이 나와 있습니다.

페이지 안에서 PDF 읽기

페이지에 붙인 PDF는 파일 이름 바로 아래에 내용이 보입니다. 미리보기 안에서 스크롤하면 쪽이 넘어가고, 쪽 번호를 입력하면 그 쪽으로 갑니다. − / + 로 크기를 바꾸고, '너비 맞춤' 버튼을 누르면 쪽이 본문 폭에 맞춰집니다. '전체 화면' 버튼을 누르면 창 전체로 크게 읽을 수 있습니다. Esc나 닫기 버튼으로 닫으면 파일 이름 아래의 미리보기가 읽던 쪽으로 옮겨 갑니다. 브라우저의 뒤로 가기는 평소처럼 이전 화면으로 가면서 전체 화면도 닫습니다. PDF 글자는 드래그해서 복사할 수 있고, PDF 안의 웹 링크는 새 탭에서 열립니다. 같은 PDF의 다른 쪽을 가리키는 링크를 누르면 그 쪽으로 스크롤됩니다.

10 MB까지의 PDF는 스크롤해서 닿으면 바로 열립니다. 그보다 큰 파일은 '미리보기 불러오기 (크기)' 버튼이 나오니, 데이터를 쓸지 직접 정하시면 됩니다. 브라우저의 데이터 절약 모드가 켜져 있으면 모든 PDF가 이 버튼을 기다립니다. '미리보기 접기'를 누르면 한 줄로 접히고, 이 브라우저에서는 다음에도 접힌 채로 보입니다. 미리보기는 내 화면에만 있는 것이라 스크롤하거나 확대해도 다른 사람의 페이지는 바뀌지 않고, 각자 자기 쪽을 읽습니다. 암호가 걸렸거나 깨진 PDF, 5,000쪽이 넘는 PDF는 미리 볼 수 없으니 내려받아서 여세요. 공개 링크에서는 지금처럼 파일 이름만 보입니다.

필기가 있는 페이지와 필기 모드에서는 필기 위치가 어긋나지 않도록 PDF가 파일 이름만 보입니다. 필기는 페이지 높이를 기준으로 놓이고, PDF 위에는 필기할 수 없습니다. 내가 열어 둔 페이지에 다른 사람이 첫 필기를 하면 1분 안에 미리보기가 사라집니다.

페이지 확인 표시

페이지 내용이 언제까지 맞는지 표시해 둘 수 있습니다. 머리글 ⋯ 메뉴에서 '페이지 확인 표시…'를 누르고 유효 기간을 30일, 90일, 180일 가운데 고르거나 '날짜 지정…'으로 날짜를 정한 다음(최대 1년), 필요하면 메모를 적고 '확인됨으로 표시'를 누르면 됩니다. 제목 아래에 '확인됨' 표시가 붙고, 그 날짜가 지나면 '다시 확인 필요'로 바뀝니다. 확인한 뒤에 바뀐 섹션이 몇 개인지도 같이 나옵니다. 페이지를 편집할 수 있는 사람이면 확인 표시를 할 수 있는데, 페이지 담당자가 정해져 있으면 담당자나 워크스페이스 소유자, 관리자만 할 수 있습니다. '확인된 페이지 전체 보기'에서는 다시 확인이 필요한 페이지, 7일 안에 만료되는 페이지, 확인된 페이지를 한꺼번에 볼 수 있습니다. 연결한 AI 에이전트도 이 표시를 보고, 기한이 지난 페이지는 그렇다고 안내받습니다.

발표 모드

머리글 ⋯ 메뉴의 '발표 모드'를 누르면 문서를 전체 화면 슬라이드로 보여 줍니다. 웹에 공개한 페이지에도 같은 버튼이 있습니다. 장은 페이지의 제목에서 나뉩니다. 두 번 이상 쓴 제목 수준 중 가장 큰 수준과 그보다 큰 제목마다 새 장이 시작됩니다(맨 위 H1 하나에 H2 절들이면 H1 한 장과 H2마다 한 장). 구분선에서도 새 장이 시작됩니다. ← / →(PageUp / PageDown, Space, Home / End도 됩니다)나 화면을 밀어서 넘기고, Esc를 누르면 나옵니다. 화면보다 긴 장은 마우스 휠, 위아래로 밀기, ↑ ↓로 스크롤합니다. 발표 모드를 열 때의 내용을 복사해서 보여 주기 때문에, 그 사이에 다른 사람이 고친 내용은 다시 열어야 보입니다. 슬라이드 안의 버튼은 눌리지 않습니다.

필기 모드

페이지 머리글 ⋯ 메뉴의 '필기 모드'를 누르면 필기 모드가 켜지고, 문서 위에 펜이나 손가락으로 글씨를 쓰거나 형광펜을 칠할 수 있습니다. 태블릿에서 쓰기 좋은 편입니다. 끝내실 때는 Esc를 누르거나 '완료'를 누르시면 됩니다.

도구 막대의 '전체' 버튼은 이 페이지의 필기를 한꺼번에 지웁니다. 실수로 눌러서 필기가 다 날아가는 일이 없도록 한 번 누르면 '전체 지울까요?'로 바뀌고, 3초 안에 한 번 더 눌러야 실제로 지워집니다. 그리고 필기는 페이지의 기존 필기를 다 불러온 다음부터 저장됩니다. 불러오지 못했을 때는 알림이 뜨고, 불러올 때까지는 새로 쓴 필기도 저장되지 않습니다.

연결한 AI 에이전트는 기본적으로 필기를 보지 못합니다. 워크스페이스 소유자나 관리자가 워크스페이스 설정 › 연결된 에이전트에서 '에이전트가 필기를 읽을 수 있음'을 켜야 볼 수 있습니다. 켜 두면 에이전트가 필요할 때 페이지의 펜·형광펜 필기를 그림으로 받아 갑니다. 본문 글은 지금처럼 따로 읽습니다. 처음에는 꺼져 있고, 다시 끄면 바로 적용됩니다.

데이터베이스

데이터베이스는 '새 데이터베이스'로 만듭니다. 행 하나하나가 페이지이기 때문에, '행 페이지 열기'를 누르면 그 행을 보통 문서처럼 열어서 내용을 쓸 수 있습니다.

뷰는 표, 보드, 캘린더, 갤러리, 타임라인, 차트, 폼, 리스트가 있고 뷰 탭의 '새 뷰'로 추가합니다. 속성은 '새 속성 추가'로 만들며 종류는 텍스트, 숫자, 선택, 다중 선택, 날짜, 체크박스, 사람, URL, 이메일, 전화번호, 관계형, 롤업, 수식이 있습니다. 여기에 저절로 채워지는 속성으로 생성 일시, 최종 편집 일시, 생성자, 최종 편집자, ID가 있습니다. 이런 자동 속성은 직접 고칠 수 없고, 에이전트가 고친 행이면 최종 편집자에 '(via Claude)'처럼 어느 앱을 거쳤는지도 같이 나옵니다. ID는 TASK-12처럼 접두어와 번호로 행마다 번호를 매기는데, 한 번 준 번호는 다시 쓰지 않고, 속성을 처음 추가하면 이미 있던 행에도 번호가 붙습니다.

'정렬 · 필터'에서 뷰마다 정렬 순서와 필터, 표시할 필드를 따로 정할 수 있고, 보드는 선택 속성을 기준으로 묶입니다. 필터의 '일치'에서 '모두'를 고르면 조건을 다 만족하는 행만, '하나라도'를 고르면 하나만 맞아도 남깁니다. 조건마다 '아님'을 켜면 반대로 맞지 않는 행만 남고, '그룹 추가'로 조건 몇 개를 묶어 그 안에서 따로 모두/하나라도를 정할 수도 있습니다.

데이터베이스 ⋯ 메뉴의 '하위 항목 켜기'를 누르면 '상위 항목' 속성이 생기고, 행을 다른 행 아래에 둘 수 있습니다. 하위 항목은 표에서 행 메뉴의 '하위 항목 추가'로 만들거나 상위 항목을 골라 주면 됩니다. 표와 리스트 뷰에서는 트리로 보이고 접었다 펼 수 있으며, 뷰 설정의 '중첩 / 평면'으로 바꿉니다. 행을 자기 자신이나 자기 하위 항목 아래에 둘 수는 없습니다.

데이터베이스를 문서 안에 보여 주고 싶으면 /데이터베이스 보기를 입력하고 데이터베이스와 보기를 고르세요. 블록은 읽는 사람이 볼 수 있는 행만으로 그 보기를 보여 주고, 데이터베이스가 바뀌면 함께 바뀝니다. 행을 누르면 그 행이 열리고, '전체 보기'를 누르면 데이터베이스 전체 화면으로 갑니다. 보기는 블록 머리에서 바꿉니다. 이 블록에서는 칸을 고칠 수 없고, 볼 권한이 없는 사람에게는 '볼 수 없는 데이터베이스'로만 보입니다.

템플릿의 '에이전트 작업 보드'는 AI 에이전트 여럿이 일을 나눠 맡을 때 쓰는 데이터베이스입니다. 하위 작업, 담당(사람이나 그 사람의 에이전트), 완료 근거, TASK-n ID가 들어 있습니다. 쓰는 방법은 RECIPES.ko.md에 있습니다.

표는 키보드로도 다룰 수 있습니다. 칸을 누르거나 Tab으로 표에 들어온 다음 화살표, Tab / ⇧Tab, Home / End로 칸을 옮겨 다니면 됩니다. Enter나 F2를 누르면 칸을 편집합니다(선택 속성이면 목록이 열리고 체크박스면 체크가 바뀝니다). 글자 칸에서는 Enter를 누르면 저장하고 아래 칸으로 내려가고, Esc를 누르면 취소됩니다. Space는 체크박스를 켜고 끄고, ⌫는 고른 칸을 비우고, ⇧+화살표는 ⌘C / ⌘V로 복사할 범위를 넓힙니다. ⌘Enter를 누르면 새 행이 생기고 바로 제목을 쓸 수 있습니다. 맨 아래 행에서 Enter로 저장해도 새 행이 생깁니다. ⌘⇧Enter는 그 행을 페이지로 엽니다. 편집 권한이 없으면 칸 이동만 됩니다. 이 키들도 단축키 목록의 '데이터베이스 표'에 있고 거기서 바꿀 수 있습니다.

표 뷰에서는 열 머리글의 오른쪽 끝을 끌어서 열 너비를 바꿀 수 있습니다. 바꾼 너비는 뷰에 저장되기 때문에 그 뷰를 여는 사람 모두에게 똑같이 보입니다. 끝을 더블클릭하면 자동 너비로 돌아가고, 키보드로 끝에 초점을 둔 다음 ←/→를 눌러도 됩니다. 데이터베이스를 편집할 수 없는 사람이 너비를 바꾸면 자기 화면에서만 바뀝니다. 칸에 다 안 들어가는 긴 글은 '…'로 잘리고, 마우스를 올리면 전체가 보입니다. 열이 많은 표나 보드는 페이지 폭 끝까지 넓게 펼쳐지고, 사이드바의 ⋯ 메뉴에 있는 '전체 너비'나 설정의 본문 폭도 데이터베이스 페이지에 똑같이 적용됩니다.

관계형 속성은 다른 데이터베이스의 행과 연결할 때 씁니다. '연결된 데이터베이스에도 표시 (양방향)'를 켜 두면 상대 데이터베이스 쪽에서도 연결이 보입니다. 롤업은 이렇게 연결된 행의 값을 모아 계산하는 속성으로, 개수, 합계, 평균, 최솟값과 최댓값, 가장 이른 날짜와 늦은 날짜, 체크 비율, 고유값 중에서 고를 수 있습니다.

Excel이나 Google Sheets에서 복사한 칸은 그대로 붙여 넣으셔도 되고, 'CSV / Excel 가져오기…'로 파일을 올리셔도 됩니다. 지금 보고 있는 뷰는 '현재 뷰를 CSV로 내보내기'나 '현재 뷰를 Excel로 내보내기'로 파일로 받을 수 있습니다. 'Google Sheets 동기화…'는 웹에 게시한 시트를 주기적으로 가져오는 기능인데, 아직 실험 기능이라 서버에서 켜 둔 경우에만 보입니다.

행 템플릿

행 템플릿을 만들어 두면 새 행을 만들 때 제목과 속성값, 본문이 미리 채워집니다. '새 행' 옆의 ▾에서 '새 템플릿'을 누르거나 ⋯ 메뉴의 '행 템플릿…'에서 만들 수 있고, 편집 화면은 보통 페이지와 같아서 본문도 페이지처럼 쓰시면 됩니다. 날짜 속성에는 '오늘'이나 '오늘부터 며칠 뒤'를, 사람 속성에는 '행을 만든 사람'을 넣어 둘 수 있습니다. 제목과 텍스트에는 {{date}}, {{input:주제|주간}} 같은 템플릿 변수를 그대로 쓸 수 있습니다(TEMPLATES.ko.md).

'새 행' 버튼을 누르면 '새 행의 기본 템플릿'으로 정해 둔 템플릿이 쓰이고, 기본 템플릿이 없으면 빈 행이 생깁니다. ▾를 누르면 다른 템플릿이나 빈 행을 골라서 만들 수 있는데, 이렇게 만든 행은 바로 열립니다. 보드 열의 +나 캘린더 날짜의 +로 만들 때도 기본 템플릿이 쓰이고, 그 열의 값이나 날짜가 그 위에 덮어써집니다.

템플릿은 데이터베이스를 볼 수 있는 사람이면 누구나 쓸 수 있고, 고치려면 그 데이터베이스를 편집할 수 있어야 합니다. 편집 잠금이 걸려 있으면 템플릿도 같이 잠깁니다. 템플릿은 페이지가 아니기 때문에 검색이나 백링크, 그래프, 사이드바에는 나오지 않습니다.

차트

페이지에서 /차트(또는 /chart)를 입력하고 데이터를 고릅니다. 데이터베이스 전체나 특정 뷰에 보이는 행만 쓸 수 있고, 쿼리 블록 문법으로 쓴 쿼리도 쓸 수 있습니다. 그다음 차트 종류와 '묶을 기준', '값'을 고르면 됩니다. 날짜는 일·주·월 단위로 묶을 수 있습니다. '나눌 기준'을 고르면 묶음 안을 한 번 더 나눠서 누적 막대나 여러 개의 선으로 그립니다. '값'은 행 개수를 세거나 숫자 속성의 합계, 평균, 최솟값, 최댓값을 구합니다.

차트에는 설정만 저장됩니다. 페이지를 여는 사람마다 자기가 볼 수 있는 행으로 계산한 숫자를 보게 되고, 데이터베이스를 볼 권한이 없으면 숫자 대신 그 이유가 나옵니다. 다른 사람이 데이터베이스를 고치면 20초 안쪽으로 다시 그려지고, 내가 고친 건 바로 반영됩니다.

데이터베이스 자체를 차트로 볼 수도 있습니다. 뷰를 추가할 때 '차트'를 고르면 되고, 그 뷰의 필터에 걸린 행만 셉니다.

마크다운으로 내보내면 차트는 숫자 표로 바뀝니다. 공개 링크에서는 차트의 데이터베이스가 공유한 폴더 안에 있을 때만 표로 보여 줍니다.

폼

폼은 응답을 받아서 데이터베이스에 쌓는 뷰입니다. 응답 하나가 행 하나가 됩니다. 뷰를 추가할 때 '폼'을 고르고 '폼 편집'을 누르면 질문을 고를 수 있습니다. 제목과 텍스트, 숫자, 선택, 다중 선택, 날짜, 체크박스, URL, 사람 속성을 질문으로 쓸 수 있고, 순서는 '위로'와 '아래로'로 바꿉니다. 꼭 받아야 하는 질문은 '필수'를 켜고, 질문 아래에 설명이 필요하면 '도움말'에 적으면 됩니다. 폼 제목과 설명, 버튼 문구, 보낸 뒤 보여 줄 말도 여기서 정합니다. 멤버는 앱 안에서 바로 폼을 작성할 수 있습니다.

워크스페이스 밖의 사람에게도 받고 싶으면 소유자나 관리자가 '공개 링크 켜기'를 누르고 링크를 복사해서 전하면 됩니다. 링크를 아는 사람은 로그인 없이 응답을 보낼 수 있고, 데이터베이스의 행이나 다른 사람의 응답은 볼 수 없습니다. 사람과 관계형 질문은 공개 폼에서 빠집니다. '끄기'를 누르면 링크가 바로 막힙니다. 데이터베이스를 휴지통에 넣거나 개인 페이지로 바꿨을 때, 워크스페이스에서 공개 링크를 껐을 때, 링크를 켠 사람이 더는 행을 추가할 수 없게 됐을 때도 링크는 저절로 닫힙니다. 공개 폼으로 들어온 응답은 활동 화면에 "링크를 켠 사람 via public form"으로 나오고, AI가 고친 것이 아니라 사람이 넣은 것으로 셉니다.

수식 속성

속성 종류에서 '수식'을 고르면 같은 행의 다른 속성으로 값을 계산하는 속성이 생깁니다. 계산된 값이라 칸에 직접 입력할 수는 없습니다. 속성을 만들 때 아래처럼 수식을 적습니다.

  • prop("가격") * prop("수량")
  • if(prop("완료"), "✓", "")
  • dateBetween(prop("마감"), now(), "days")
함수하는 일
prop("이름")같은 행의 속성 값("Title"은 행 제목). 선택은 옵션 이름, 다중 선택은 이름을 ", "로 이은 글, 체크박스는 true나 false가 되고 사람과 관계형은 빈 값입니다
if(조건, a, b)조건이 참이면(비어 있지 않고 0이 아니면) a, 아니면 b
and(a, b, …), or(a, b, …), not(a)논리 연산. and, or, not이나 &&, ||, !로 써도 됩니다
concat(a, b, …)인자를 모두 글자로 이어 붙임
length(x)x를 글자로 바꿨을 때의 글자 수(빈 값은 0)
round(n, 자릿수)소수점 0~10자리로 반올림(자릿수는 생략 가능)
min(a, …), max(a, …)가장 작은 수, 가장 큰 수(빈 값은 건너뜀)
abs(n)절댓값
now()지금 날짜와 시각
dateAdd(날짜, n, 단위)날짜를 n단위만큼 옮김. 단위는 years, months, weeks, days, hours, minutes
dateBetween(a, b, 단위)a에서 b를 뺀 값을 단위로 센 정수

연산자는 +(숫자는 더하고 글자가 섞이면 이어 붙입니다), -, *, /, %, =, !=, <, <=, >, >=가 있고, 글자는 따옴표로 감쌉니다. 날짜는 UTC 기준으로 계산하기 때문에 자정 무렵에는 내 시간대의 '오늘'과 하루 차이가 날 수 있습니다. 계산이 안 되는 칸에는 값 대신 순환 참조, 0으로 나눔, 없는 속성 같은 오류가 표시됩니다. 수식이 읽는 속성의 이름을 바꾸면 수식도 따라서 바뀝니다. 다른 속성처럼 필터, 정렬, 보드 묶기, 차트에 쓸 수 있고 내보낸 파일에도 계산된 값이 들어갑니다.

자동화

데이터베이스 ⋯ 메뉴에서 '자동화…'를 열고 '새 자동화'를 누릅니다. 언제 돌지(행이 추가될 때, 속성이 바뀔 때나 특정 값으로 바뀔 때만, 날짜 속성이 N일 남았을 때), 조건(없어도 됩니다), 그리고 무엇을 할지를 정합니다. 할 수 있는 건 값 바꾸기, 사람 지정, 알림 보내기, 등록된 웹훅 보내기, 다른 데이터베이스에 행 추가, 그 사람의 AI 연결에 행 넘기기이고 규칙 하나에 다섯 개까지, 데이터베이스 하나에 규칙 20개까지 둘 수 있습니다. 규칙은 마지막으로 저장하거나 켠 사람의 권한으로 변경 직후에 돌고, 바뀐 내용에는 "<이름> via automation: <규칙>"이 남습니다. 실행 기록에서 실행마다 결과를 볼 수 있고, 다섯 번 연달아 실패하면 규칙이 꺼지면서 만든 사람에게 알림이 갑니다. 게스트나 공개 폼 답변, AI 연결 때문에 돈 실행은 다른 데이터베이스에 쓰지 못합니다. 연결한 AI 에이전트는 규칙을 볼 수는 있지만 만들 수는 없습니다.

그래프, 캔버스, 쿼리 블록

그래프(⌘G)는 워크스페이스의 모든 페이지와 링크를 한 화면에 그려 줍니다. 그래프 설정에서 제목으로 찾거나, 연결 없는 페이지 표시, 태그 노드 표시, 최상위 폴더별 색을 켜고 끌 수 있고, 노드끼리 당기고 밀어내는 힘도 조절할 수 있습니다. 지금 보고 있는 페이지 주변만 보고 싶을 때는 오른쪽 패널의 로컬 그래프가 더 편합니다.

캔버스는 끝없이 넓은 보드에 텍스트 카드, 페이지 카드, 링크 카드를 늘어놓는 기능입니다. 이미지는 끌어다 놓으면 카드가 됩니다. 옵시디언의 .canvas 형식과 호환되도록 만들었기 때문에 옵시디언과 파일을 주고받을 수 있습니다. 이미 쓴 문서가 있다면 문서의 ⋯ 메뉴에서 '캔버스로 펼치기'를 눌러 캔버스로 바꿀 수도 있습니다. 다만 캔버스는 아직 웹에 공유할 수 없습니다.

쿼리 블록은 / › 쿼리로 넣고, LIST FROM #project나 TABLE status FROM "Projects"처럼 Dataview 문법으로 조건을 적으면 맞는 페이지를 표나 목록으로 보여 줍니다. 페이지가 바뀌면 결과도 따라 바뀝니다. 문법은 QUERY.ko.md에 정리해 두었습니다.

비슷한 구조의 페이지를 자주 만드신다면 템플릿을 쓰시는 편이 좋습니다. '템플릿에서 시작'으로 페이지 하나나 하위 페이지까지 갖춘 구조를 한 번에 만들 수 있고, 직접 만든 페이지는 ⋯ 메뉴의 '템플릿으로 저장'으로 템플릿이 됩니다. 자세한 내용은 TEMPLATES.ko.md를 참고하시기 바랍니다.

할 일과 캘린더

문서 안의 체크리스트 항목에 날짜를 붙이면 할 일로 잡힙니다. - [ ] 보고서 📅 2026-09-30이나 [due:: 2026-09-30]처럼 쓰시면 됩니다.

사이드바의 '마감'에서는 날짜가 지난 일, 이번 주, 앞으로 30일 안의 할 일을 모아 보여 줍니다. 여기 있는 '할 일 추가…'에 적으면 "Tasks" 문서에 체크리스트 항목으로 들어갑니다. '캘린더'는 날짜가 있는 항목을 월이나 주 단위로 보여 주는 화면인데, 빈 날짜를 누르면 그 날짜로 할 일이나 페이지, 데일리 노트를 만들 수 있고 항목을 끌어서 다른 날로 옮길 수도 있습니다.

Google 캘린더나 Apple 캘린더, Outlook에서 함께 보고 싶으시면 설정 › 연결 › 캘린더 구독 (iCal)에서 구독 링크를 만드시면 됩니다. 이 링크를 아는 사람은 누구나 그 항목을 읽을 수 있으니 다른 사람에게는 알려 주지 않으셔야 합니다.

함께 쓰기

동시 편집

한 문서나 캔버스를 여러 사람이 동시에 고칠 수 있습니다. 다른 사람의 커서가 화면에 보이고, 머리글에 지금 들어와 있는 사람과 연결 상태가 표시됩니다. 연결이 끊긴 동안 고친 내용은 다시 연결되면 합쳐집니다. 오프라인 사본을 켜 두셨다면('오프라인에서 쓰기' 참고) 기기에 보관되고, 꺼 두셨다면 탭을 열어 두는 동안만 남습니다.

아직 서버에 닿지 않은 편집이 있으면 연결 상태 점이 주황색으로 바뀝니다. 편집이 이 기기에 보관되어 있으면 '아직 올라가지 않음', 이 탭에만 있으면 '아직 저장되지 않음'이라고 나옵니다. 마우스를 올리면 '서버에 아직 닿지 않은 편집이 있습니다. 저장될 때까지 이 탭을 닫지 마세요.'라는 설명이 보이고, 이때만 탭을 닫거나 새로 고치려고 하면 브라우저가 한 번 더 물어봅니다. 앱 안에서 다른 페이지로 옮겨 가는 건 괜찮습니다. 떠난 페이지의 편집은 서버에 닿을 때까지 붙잡아 둡니다.

서버가 업데이트되기 전에 열어 둔 탭은 이전 버전 앱이 그대로 돌고 있습니다. 이런 탭은 자기가 모르는 내용(0.20의 단 나누기 같은)이 들어 있는 페이지를 읽을 수만 있고 고칠 수는 없으니 새로고침해 주세요. 0.20부터는 이런 페이지 위에 '이 페이지에는 새 버전에서만 편집할 수 있는 내용이 있습니다. 새로고침하세요.'라고 나오고, 0.19 탭에서는 잠긴 페이지처럼 보입니다.

코멘트

코멘트는 오른쪽 패널의 코멘트에서 답니다. '현재 블록에 코멘트'를 누르면 커서가 있는 블록에 스레드가 달리고, '새 스레드'를 누르면 페이지 전체에 대한 스레드가 생깁니다. 코멘트 안에서도 @로 멘션할 수 있고, '답글'로 대화를 이어 가다가 이야기가 끝나면 '해결'을 누르시면 됩니다.

알림

오른쪽 위의 종 버튼에는 모든 워크스페이스의 알림이 함께 모입니다. 누군가 페이지나 코멘트에서 나를 멘션했을 때, 따라가는 스레드에 답글이 달렸을 때, 나를 페이지 담당자로 정하거나 데이터베이스의 사람 칸에 넣었을 때, 내가 팔로우하는 페이지가 바뀌었을 때, 그리고 나중에 보기에 걸어 둔 리마인더 시간이 됐을 때 알림이 옵니다. AI 에이전트가 쓴 멘션은 배지나 메일 없이 조용히 들어오고 요약 메일에 묶여서 갑니다. 에이전트가 여러 번 멘션해도 시끄럽지 않게 하려고 이렇게 정했습니다.

앱을 닫아 둔 동안에도 알림을 받고 싶으시면 푸시 알림을 켜시면 됩니다. 설정 › 알림 › 푸시 알림 › 이 기기에서 '켜기'를 누르면 브라우저가 알림 권한을 한 번 묻습니다. 어떤 알림을 푸시로 받을지 고르거나, 모든 기기의 푸시를 잠깐 멈추거나, 잠금 화면에는 내용 없이 "새 알림"만 뜨게 할 수 있습니다. 기기가 제대로 받는지는 '테스트 보내기'로 확인합니다. iPhone·iPad는 먼저 홈 화면에 추가하고 그 아이콘으로 열어야 합니다(iOS 16.4 이상). 다만 실제 iPhone·iPad에서는 아직 확인하지 못했습니다. 기기에서 로그아웃하면 그 기기로 가던 푸시도 멈춥니다. 데이터베이스 자동화가 보내는 알림은 멘션으로 옵니다. 푸시는 서버가 HTTPS여야 쓸 수 있어서, 설정에 이 서버에서는 쓸 수 없다고 나오면 서버 관리자에게 물어보세요.

페이지 팔로우

페이지 머리글 ⋯ 메뉴의 '페이지 알림'에서 그 페이지의 알림을 얼마나 받을지 정합니다. '이 페이지 팔로우'나 '페이지와 하위 페이지 팔로우'를 고르면 그 페이지에서 일어나는 일을 받아 보게 되고, 기본값은 '멘션만'입니다. 아예 받고 싶지 않으면 '알리지 않음'이나 '음소거'를 고르시면 되는데, 음소거는 멘션 알림까지 막고 나에게 온 승인 요청만 통과시킵니다. '상속'은 상위 페이지나 워크스페이스 설정을 그대로 따릅니다. 'AI가 여기를 편집하면 하루 요약 받기'를 켜 두면 그 페이지 아래에서 AI가 고친 내용을 하루에 한 번 모아서 받을 수 있습니다.

설정 › 알림에서는 지금 팔로우 중인 항목을 한꺼번에 보고, 메일을 어떻게 받을지 정합니다. '바로 메일 받기'를 켜면 멘션과 답글, 담당 지정이 생길 때마다 메일이 오고, '요약 메일'은 매일이나 매주 한 번 나머지를 모아서 보내 줍니다. 서버에 메일 설정이 되어 있지 않으면 이 부분은 꺼져 있고 알림은 앱 안에만 쌓입니다.

스레드 따라가기

코멘트 스레드를 새로 열거나 답글을 달면 그 스레드를 자동으로 따라가게 됩니다. 그 뒤로 다른 사람이 답글을 달면 종 알림이 오고, 메일 설정에 따라 메일도 갑니다. 내가 쓴 적 없는 스레드라도 코멘트 패널의 스레드 카드에서 '스레드 따라가기'를 누르면 같이 받아 볼 수 있고, '따라가는 중'을 다시 누르면 그만 따라갑니다. 한 번 그만둔 스레드는 다시 답글을 달아도 자동으로 따라가지 않습니다.

사이드바의 '스레드'에는 따라가는 스레드 중 새 답글이 달린 것만 최신순으로 모입니다. 새 답글이 몇 개인지, 마지막 답글이 무엇인지 같이 나오고, 여기서 스레드를 열면 읽은 것으로 처리되면서 종에 있던 같은 스레드 알림도 읽음으로 바뀝니다. '새 답글 없는 스레드도 보기'를 켜면 따라가는 스레드 전체가 나오니 정리할 때 쓰시면 됩니다.

설정 › 알림에 스위치가 두 개 있습니다. '내가 시작하거나 답글 단 스레드 자동으로 따라가기'를 끄면 직접 누른 스레드만 따라가고, '따라가는 스레드의 답글 알림 받기'를 끄면 답글은 스레드 화면에만 쌓이고 배지나 메일은 오지 않습니다. 멘션은 이 설정과 상관없이 그대로 옵니다.

나중에 보기

페이지, 코멘트 스레드, 알림을 '나중에 보기'에 저장해 두고 나중에 사이드바의 '나중에 보기'에서 다시 볼 수 있습니다. 페이지는 머리글 ⋯ 메뉴의 '나중에 보기'(⌘P 팔레트의 '이 페이지 나중에 보기에 저장'도 같습니다), 스레드는 코멘트 패널 스레드 카드의 시계 버튼, 알림은 종 목록에서 항목 오른쪽의 시계 버튼으로 저장합니다.

같은 창에서 리마인더도 걸 수 있습니다. '20분 뒤', '오늘 저녁'(18시), '내일'(9시), '다음 주 월요일'(9시) 중에 고르거나 날짜와 시간을 직접 넣으면 되고, 시간은 지금 쓰는 기기의 시간대 기준입니다. 시간이 되면 종 알림이 오고, '바로 메일 받기'를 켜 두었으면 메일도 갑니다. 리마인더 시간이 지난 항목 수는 사이드바에 빨간 숫자로 나옵니다. 다 본 항목은 '완료'를 눌러 완료 탭으로 옮기거나 지우면 됩니다.

저장한 페이지를 더는 볼 수 없게 되면(페이지가 비공개로 바뀌었거나, 워크스페이스에서 나갔거나, 워크스페이스가 2단계 인증을 요구하게 된 경우) 항목은 목록에 남지만 제목은 보이지 않고 리마인더도 가지 않습니다. 지우는 것은 언제든 됩니다.

연결한 AI 에이전트는 later 도구로 나중에 보기 목록을 읽을 수만 있고, 항목을 추가하거나 리마인더를 걸 수는 없습니다.

활동

사이드바의 '활동'은 사람과 AI가 최근에 바꾼 내용을 최신순으로 보여 주는 화면입니다. 사람이 한 것만, 또는 AI가 한 것만 보거나, 앱이나 멤버, 페이지, 변경 종류로 걸러 볼 수 있습니다. '변경 내용 보기'를 누르면 실제로 어떤 줄이 바뀌었는지 나옵니다. 에이전트가 한 변경에는 '되돌리기'가 붙어 있습니다(에이전트 편집 되돌리기).

멤버

멤버는 워크스페이스 메뉴의 '멤버 관리'에서 봅니다. 다른 워크스페이스에서 이미 함께하고 있는 사람은 이름이나 이메일로 찾아서 바로 추가할 수 있고, 처음 오는 사람에게는 초대 링크를 보내시면 됩니다. '초대 링크 복사'는 사이드바 맨 아래에도 있습니다.

내 상태

설정 › 계정 › 상태에서 '상태 설정'을 누르면 이모지와 짧은 상태 메시지를 남길 수 있습니다. 예를 들어 "시험 기간, 금요일까지"처럼 적고, '자동 해제'에서 1시간 뒤, 오늘 밤, 이번 주 끝, 날짜와 시각 지정… 가운데 하나를 고르면 그때 저절로 지워집니다. 계속 두고 싶으면 '해제 안 함'을 고르면 됩니다. 상태는 멤버 목록과 @ 멘션 목록, 그리고 페이지 머리글에 나오는 지금 접속 중인 사람 표시에 보입니다. 상태는 계정마다 하나라서 모든 워크스페이스에 똑같이 나옵니다. AI 에이전트도 나를 멘션하거나 표의 담당자로 넣을 때 이 상태를 봅니다.

페이지별 권한과 게스트

페이지의 공유 창 위쪽 '사람' 영역에서 한 사람에게 그 페이지와 하위 페이지에 대한 권한을 줄 수 있습니다. 권한은 네 가지입니다.

권한읽기코멘트편집공유 관리
볼 수 있음O
코멘트 가능OO
편집 가능 (멤버 기본값)OOO

멤버는 원래 공유 페이지를 모두 편집할 수 있습니다. 여기서 권한을 정하면 그 페이지 아래에서만 기본값 대신 그 권한이 적용됩니다. 계약서 폴더는 특정 멤버에게 보기만 허용한다든지, 프로젝트 담당자에게 전체 권한을 줘서 그 폴더의 공유를 맡기는 식으로 씁니다. 소유자와 관리자는 언제나 전체 권한이라 따로 정할 수 없고, 멤버의 권한을 바꿀 수 있는 사람은 그 페이지에 전체 권한이 있는 사람과 소유자, 관리자입니다.

게스트는 워크스페이스 멤버가 아닌 사람입니다. 이메일 주소를 넣으면 이 서버에 계정이 있는 사람은 바로 권한이 생기고, 계정이 없는 주소로는 초대 메일이 갑니다. 서버에 메일 설정이 없으면 초대 링크가 나오니 복사해서 직접 전해 주시면 됩니다. 받은 사람은 같은 이메일 주소로 로그인하거나 가입한 뒤 링크를 열어야 초대가 받아집니다. 게스트에게는 공유받은 페이지와 그 하위 페이지만 보이고, 워크스페이스의 다른 페이지나 검색, 그래프, 멤버 목록, 설정은 보이지 않습니다. 게스트는 보기, 코멘트, 편집까지만 받을 수 있고 공유 관리는 할 수 없으며, 목록에는 '게스트' 표시가 붙습니다. 게스트에게 공유한 데이터베이스는 게스트도 열어서 행을 볼 수 있습니다. 게스트가 볼 수 없는 페이지로 가는 링크는 가려지고, '편집' 권한이면 행을 추가하고 칸을 고칠 수 있지만 사람을 지정하거나 속성과 뷰를 바꿀 수는 없습니다.

누가 게스트를 초대할 수 있는지는 워크스페이스 설정 › 일반의 '게스트를 초대할 수 있는 사람'에서 정합니다. 아무도 못 하게 하거나, 소유자만, 소유자와 관리자(기본값), 그 페이지를 편집할 수 있는 멤버까지 중에서 고르면 됩니다. 멤버는 자기가 가진 것보다 높은 권한을 줄 수 없습니다. 상위 페이지에서 준 권한은 하위 페이지에 '상속'으로 보이고, 바꾸려면 상위 페이지에서 바꾸면 됩니다. 편집 잠금은 따로 걸리기 때문에, 편집 가능한 게스트라도 잠긴 페이지는 잠금 설정이 허용해야 고칠 수 있습니다.

워크스페이스 설정 › 멤버 아래 게스트 목록에서는 게스트마다 어떤 페이지에 어떤 권한이 있는지 볼 수 있고, 소유자와 관리자는 여러 명을 골라 한꺼번에 내보낼 수 있습니다. 게스트가 워크스페이스에 가입하면 보통 멤버가 되고, 워크스페이스에서 내보낸 사람은 페이지별 권한도 함께 사라집니다. 게스트는 웹 앱으로만 들어올 수 있고, 그 사람의 API 토큰이나 AI 연결로는 게스트로 들어간 워크스페이스가 보이지 않습니다. 워크스페이스가 2단계 인증을 요구하면 게스트에게도 똑같이 적용됩니다.

웹에 공유

페이지를 로그인 없이 볼 수 있는 링크로 공개하는 기능입니다. 공개와 공유 중지는 워크스페이스 소유자와 관리자만 할 수 있습니다.

  1. 페이지 머리글의 '공유' 버튼이나 트리 ⋯ 메뉴의 '공유…'를 누릅니다.
  2. '웹에 공개'를 누른 다음 링크를 복사해서 전하시면 됩니다.
  3. 공개를 멈추고 싶을 때는 같은 창에서 '공유 중지'를 누르면 링크가 바로 막힙니다.

링크를 받은 사람은 읽기만 할 수 있고 고칠 수는 없습니다. 폴더를 공유하면 그 안의 페이지가 모두 함께 공개되는데, 개인 페이지는 빠집니다. 개인 페이지와 캔버스는 공유할 수 없습니다. 공개한 페이지에는 끼워 넣은 페이지, 데이터베이스 보기, 쿼리 결과도 보이는데, 링크에 포함된 페이지의 것만 나오고 나머지는 '이 링크에 포함되지 않은 내용이 임베드되어 있습니다.' 한 줄로 바뀝니다. Mermaid 다이어그램도 그려집니다. 지금 무엇이 공개되어 있는지는 사이드바의 '웹 공유'에서 한눈에 볼 수 있고, 워크스페이스 전체에서 웹 공개를 막고 싶으면 소유자가 워크스페이스 설정 › 공개 링크에서 끄시면 됩니다.

만료와 비밀번호

공개하기 전에 같은 창에서 링크의 만료와 비밀번호를 정할 수 있습니다. 만료는 '만료 없음', 1일 뒤, 7일 뒤, 30일 뒤 가운데 고르거나 '날짜 지정…'으로 마지막 날을 고르면 됩니다. 날짜를 고르면 그날이 끝날 때까지 열립니다. 기간은 서버 시계로 계산하기 때문에 보는 사람 컴퓨터의 시계가 틀려도 상관없습니다. 만료된 링크로 들어온 사람에게는 '만료된 링크입니다'라는 안내만 보이고 페이지 제목이나 내용은 보이지 않습니다.

'비밀번호 걸기'를 켜고 4자 이상의 비밀번호를 넣으면, 링크를 연 사람은 비밀번호를 입력해야 페이지를 볼 수 있습니다. 비밀번호는 링크와 다른 경로로 전해 주시는 게 좋습니다. 한 번 맞히면 그 링크는 12시간 동안 다시 묻지 않습니다. 비밀번호를 여러 번 틀리면 그 링크에 대한 시도가 잠시 늦춰지고, 같은 IP에서 계속 틀리면 그 IP가 일정 시간 막힙니다. 비밀번호가 걸린 링크는 메신저 미리보기에 제목과 내용이 나오지 않고 검색 엔진에도 올라가지 않습니다.

이미 공개한 링크도 바꿀 수 있습니다. 공유 창의 '만료 변경'으로 기간을 늘리거나 만료를 없앨 수 있고, 비밀번호는 '비밀번호 설정', '변경', '해제'로 다룹니다. 비밀번호를 바꾸면 이전 비밀번호로 열어 둔 사람도 다시 입력해야 합니다. 만료된 링크도 지워지지 않고 남아 있어서 다시 늘리면 같은 주소로 다시 열립니다. 사이드바의 '웹 공유'에는 링크마다 만료일, 만료됨, 비밀번호 표시가 붙습니다. 공유를 중지하면 만료와 비밀번호도 함께 지워지고, 다시 공개하면 새 주소가 만들어집니다.

소유자는 워크스페이스 설정 › 공개 링크에서 새 링크의 규칙을 정할 수 있습니다. '새 링크 기본 만료'를 정해 두면 공개할 때 그 기간이 미리 골라져 있고, 공개하는 사람이 다른 기간을 고를 수도 있습니다. '웹 공개 링크에 비밀번호 필수'를 켜면 새 링크는 비밀번호를 걸어야 공개할 수 있고 걸린 비밀번호는 해제할 수 없습니다. 두 설정 모두 이미 공개된 링크는 바꾸지 않습니다. 만료와 비밀번호를 바꾼 기록은 감사 로그에 남는데, 비밀번호 자체는 어디에도 남지 않습니다.

공개 시작 시각 예약

웹 공개 링크가 나중에 열리도록 예약할 수 있습니다. '웹에 공개'를 누르기 전에 '시작 시각 예약'을 켜고 날짜와 시각을 고르면 됩니다. 시각은 지금 쓰는 기기의 시간대 기준입니다. 그때까지 링크는 없는 링크와 똑같이 보입니다. 공개한 뒤에는 공유 창에 "…에 열림"이 나오고 '시작 시각 변경'이나 '지금 열기'로 바꿀 수 있으며, 사이드바의 '웹 공유'에도 표시가 붙습니다. 시작 시각을 바꾼 기록은 감사 로그에 남습니다.

공개 링크: 읽기, 인쇄, 내려받기

공개 링크를 연 사람은 제목 위에 있는 버튼들을 쓸 수 있습니다. 휴대폰에서는 ⋯ 버튼 하나로 모여 있습니다. '발표 모드'는 페이지를 슬라이드로 보여 줍니다. '넓게 보기'를 누르면 표, 코드, 다이어그램이 창 너비만큼 넓어지고, 글은 읽기 좋은 폭을 그대로 지킵니다. 앱에서 '전체 너비'를 켜 둔 페이지는 처음부터 넓게 열리고, 방문자가 고른 폭은 그 브라우저에 기억됩니다.

'PDF로 저장'은 브라우저의 인쇄 창을 엽니다. 거기서 'PDF로 저장'을 고르시면 됩니다. PDF에는 흰 바탕에 페이지 내용만 들어가고, 파일 이름은 페이지 제목이 됩니다.

'Markdown 내려받기'는 링크를 만든 사람이 허용했을 때만 보입니다. 공유 창의 링크 설정에서 '방문자가 Markdown으로 내려받을 수 있게'를 켜 주세요. 파일에는 공개 페이지에 보이는 내용만 들어갑니다. 새로 만든 링크는 늘 꺼진 채로 시작하고, 공개를 멈췄다가 다시 공개해도 꺼집니다.

공개 링크에는 차트가 기본으로 나오지 않습니다. 차트는 대개 링크가 공유하지 않는 데이터베이스의 숫자를 보여 주기 때문입니다. 공유 창에 이 페이지(폴더 링크면 그 안의 페이지들)의 차트 중 몇 개가 공개 링크에 나오지 않는지 나옵니다. 링크 설정에서 '공개 페이지에 차트 보여 주기'를 켜면 차트가 공개됩니다. 방문자는 차트의 제목과 막대·조각의 이름, 값을 보지만, 그 바탕이 된 행이나 데이터베이스 이름, 워크스페이스의 다른 내용은 보지 못합니다. 값은 설정을 켠 사람의 권한으로 계산합니다. 그 사람이 워크스페이스에서 빠지거나 차트의 데이터베이스를 볼 수 없게 되면 그 차트는 공개 페이지에서 빠집니다. 설정을 켜는 순간 차트가 쓰는 데이터베이스(와 질의)를 승인합니다. 나중에 누군가 다른 데이터베이스로 차트를 추가하면 그 차트는 공개 페이지에 나오지 않고, 공유 창에 "새로 추가된 차트 1개는 아직 공개되지 않습니다"가 나옵니다. 소유자나 관리자가 '이 차트도 공개'를 누르면 그때부터 그 사람의 권한으로 공개됩니다. 승인한 데이터베이스로 만든 새 차트는 바로 나옵니다. 값은 데이터베이스보다 최대 10분 늦을 수 있습니다. 폴더 링크는 폴더 안에 있는 데이터베이스의 차트를 늘 보여 줍니다. 새 링크는 차트가 꺼진 채로 시작하고, 공개를 멈췄다가 다시 공개해도 꺼집니다.

편집 잠금

공유 페이지는 멤버 누구나 고칠 수 있기 때문에, 중요한 문서는 정해진 사람만 고치도록 잠가 둘 수 있게 했습니다. 잠근 뒤에도 다른 사람은 읽고 코멘트를 남길 수 있습니다.

  1. 페이지 머리글이나 트리의 ⋯ 메뉴에서 '편집 잠금…'을 누릅니다.
  2. '이 페이지와 하위 페이지 잠그기'를 켭니다.
  3. 사람 항목에서 '담당자와 지정한 편집자만'이나 '모두(에이전트만 제한)'를 고릅니다. 편집자는 '편집자 추가…'로 넣으시면 됩니다.
  4. 에이전트(MCP AI) 항목에서 '워크스페이스 기본값', '바로 편집', '규칙으로 자동 수락', '제안만', '코멘트만', '읽기만' 중 하나를 고릅니다.

'워크스페이스 기본값'은 아래 에이전트 편집 방식에서 정한 대로 따라갑니다. '제안만'으로 두면 에이전트가 고친 내용은 바로 들어가지 않고 사람이 검토할 제안으로 남습니다. '규칙으로 자동 수락'을 고르면 이 페이지와 하위 페이지에만 쓸 자동 수락 규칙을 따로 정할 수 있습니다. 에이전트 쪽 설정은 소유자와 관리자를 포함해 모든 멤버의 에이전트에 똑같이 걸립니다. 워크스페이스 소유자와 관리자는 잠긴 페이지도 항상 고칠 수 있고, 잠금 설정을 바꿀 수 있는 사람도 이들과 페이지 담당자뿐입니다. 개인 페이지에는 잠금을 걸 수 없습니다. 잠긴 페이지에는 '잠김' 표시가 붙고, 고칠 권한이 없는 사람에게는 본문뿐 아니라 데이터베이스 칸이나 캔버스 카드, 속성까지 모두 읽기 전용으로 보입니다.

같은 창에는 에이전트 지침도 있습니다. 어떤 페이지를 지침으로 지정해 두면, AI 에이전트가 그 내용을 이 워크스페이스에서 지켜야 할 규칙으로 읽어 갑니다. 항상 읽게 할지, 조건에 맞는 페이지를 다룰 때만 읽게 할지, 이름으로 부를 때만 읽게 할지 고를 수 있습니다. 지침 페이지는 아무나 고치면 안 되기 때문에 지정하는 순간 자동으로 잠깁니다. 에이전트는 세션마다 지침을 통째로 읽기 때문에, 지침 페이지가 200줄이나 25KB를 넘으면 이 창에 경고가 뜨고 페이지의 잠금 줄에도 '김' 표시가 붙습니다. 규칙과 어디에 무엇이 있는지 정도만 남기고 자세한 내용은 링크로 빼 두시는 게 좋습니다.

Slack

워크스페이스 소유자는 워크스페이스 설정 › Slack에서 이 워크스페이스를 Slack과 연결할 수 있습니다. 화면에 순서와 주소, 그대로 붙여 넣으면 되는 앱 매니페스트가 나오고, 자세한 설정 방법은 OPERATIONS.ko.md 6절에 있습니다. 알림을 받을 채널을 정하고 멘션, 담당 지정, 검토를 기다리는 수정 제안, 답글, 하루 요약 가운데 올릴 것을 고른 다음, '테스트 메시지 보내기'로 제대로 연결됐는지 확인하면 됩니다.

Slack에는 워크스페이스 전체에 공유된 페이지만 나옵니다. 개인 페이지나 다른 워크스페이스 이야기는 올라가지 않습니다. 누군가 내 AI 에이전트에게 넘긴 일(팀 에이전트 참고)도 채널에는 올라가지 않습니다.

Slack에서 /inkling 찾을 말을 입력하면 내 노트에서 찾은 결과가 나오는데, 이 답은 나에게만 보이고 내가 Inkling에서 볼 수 있는 것만 나옵니다. /inkling help를 치면 쓸 수 있는 명령이 나옵니다. Slack 이메일과 Inkling 이메일이 같으면 계정이 저절로 연결되고, 다르면 계정이 연결되지 않았다는 안내가 나옵니다. 그때는 /inkling link를 입력하고, Inkling에 로그인한 상태에서 받은 링크를 열면 됩니다. 연결을 끊으려면 /inkling unlink를 입력합니다. Inkling 페이지 링크를 Slack에 붙여 넣으면 제목과 첫 문단이 미리보기로 나옵니다(공유된 페이지만).

내 AI 연결하기 (MCP)

Inkling에는 MCP 서버가 들어 있어서, Claude Code나 claude.ai 같은 AI 앱을 내 계정으로 연결하면 그 앱이 내 노트를 읽고 쓸 수 있습니다. 연결은 사람마다 따로 하고, AI는 연결한 사람이 볼 수 있는 페이지만 다룹니다.

연결하기

연결에 필요한 서버 주소는 설정 › 연결 › MCP 서버에서 '주소 복사'를 눌러 얻을 수 있습니다. https://notes.example.com/mcp 같은 모양입니다.

'연결 관리'를 누르면 'AI 앱 연결'이 열립니다. 쓰는 앱(Claude Code, claude.ai / Claude Desktop, Cursor, VS Code, 그 밖의 앱)을 고르면 그 앱에 맞는 명령이나 JSON 파일, URL이 나오니 그대로 복사해 넣으면 됩니다. '도구'에서 '핵심 도구'를 고르면 에이전트가 자주 쓰는 도구만 받아서 세션마다 드는 토큰이 줄고, 나머지 도구는 필요할 때 한 번 더 불러서 씁니다. 데이터베이스나 차트, 템플릿을 만드는 에이전트라면 '전체 도구'를 고르세요. 핵심 도구를 고르면 주소 뒤에 ?profile=core가 붙습니다.

Claude Code를 쓰신다면 터미널에서 다음 명령을 실행합니다.

claude mcp add --transport http inkling https://notes.example.com/mcp

그다음 Claude Code 안에서 /mcp를 실행하고 inkling을 골라 인증을 시작하면, 브라우저에 Inkling 연결 확인 화면이 뜹니다. 로그인이 필요하면 로그인하신 뒤 권한을 고르고 '허용'을 누르시면 됩니다. Claude Code가 SSH로 접속한 다른 컴퓨터에서 돌고 있다면 앱으로 돌아가는 버튼이 그 컴퓨터까지 닿지 않습니다. 이럴 때는 확인 화면의 '명령 복사'를 눌러서, 5분 안에 그 컴퓨터의 터미널에 붙여 넣어 실행하시면 됩니다.

claude.ai에서는 Customize › Connectors › + Add › Add custom connector를 열고 URL 칸에 위 주소를 넣은 뒤 연결하시면 됩니다. OAuth Client ID와 Secret 칸은 비워 두셔도 됩니다. 새 창이 뜨면 로그인하고 '허용'을 누릅니다. claude.ai는 Anthropic 서버에서 접속하기 때문에 서버가 인터넷에서 보여야 합니다.

앱이 여기서 로그인을 못 하는 경우도 있습니다. MCP 서버 로그인을 지원하지 않는 앱이거나, 서버가 http:// 주소이거나, 앱이 믿지 않는 인증서를 쓰는 경우입니다. 이럴 때는 같은 화면의 '에이전트 연결 토큰'에서 '새 토큰'을 눌러 토큰을 만드세요. 이름(편집 옆에 'via 이름'으로 나옵니다)과 읽기 전용 또는 읽기와 쓰기, 볼 수 있는 범위, 만료(7일, 30일, 90일, 365일 중 하나이고 만료 없음은 없습니다)를 고르면 됩니다. 그다음 'AI 앱 연결'의 '로그인 방식'에서 '에이전트 연결 토큰'을 고르면, 토큰이 화면에 보이는 동안은 명령이나 파일에 채워져 나옵니다. 다시 보여 주지 않으니 그때 복사해 두세요. 이 토큰은 AI 연결에만 쓸 수 있고, 로그인한 앱과 똑같이 에이전트로 취급되어 에이전트 잠금이나 워크스페이스 지침, 에이전트 편집 검토가 그대로 적용됩니다. '폐기'를 누르면 바로 막힙니다.

읽기 전용과 읽기와 쓰기

연결 확인 화면에서 권한을 고르게 되어 있습니다. '읽기와 쓰기'는 페이지를 읽고 찾는 것 말고도 만들고, 고치고, 코멘트를 달 수 있는 권한입니다. '읽기 전용'은 읽고 찾기만 하고 아무것도 바꾸지 못합니다. AI에게 노트를 맡기는 게 아직 불안하시면 읽기 전용으로 먼저 써 보시는 것도 방법입니다. 권한을 나중에 바꾸시려면 연결을 끊고 다시 연결하셔야 합니다.

AI가 볼 수 있는 범위

같은 화면에서 앱이 볼 수 있는 범위도 고릅니다. '내가 볼 수 있는 전부'는 지금처럼 내가 속한 모든 워크스페이스를 봅니다. '일부 워크스페이스만'을 고르면 체크한 워크스페이스만 보이고 나머지는 없는 것처럼 다룹니다. '페이지 하나와 그 아래 페이지만'을 고르면 그 페이지와 아래에 있는 페이지만 보이고, 새 페이지도 그 아래에만 만들 수 있습니다. 이때는 워크스페이스 템플릿도 쓰지 못합니다.

범위는 다시 연결하지 않아도 설정 › 연결 › '연결 관리'에서 '범위 바꾸기'로 바꿀 수 있습니다. 범위 안의 페이지에서 범위 밖 페이지로 걸린 링크는 그 페이지에 적힌 링크 글자만 보입니다.

AI가 할 수 있는 일과 못 하는 일

연결된 AI는 내가 속한 워크스페이스의 공유 페이지와 내 개인 페이지를 볼 수 있습니다. 페이지를 찾아 읽고(필요하면 한 부분만 읽기도 합니다), 지난번 이후 바뀐 내용을 따라가고, 자리를 비운 사이 무슨 일이 있었는지 한 번에 받아 볼 수도 있습니다. 페이지를 만들거나 일부를 고치고(바로 고치지 않고 제안만 남길 수도 있습니다), 데이터베이스를 만들거나 행을 넣고, 코멘트와 답글을 답니다. 내가 시작한 스레드라면 해결 처리도 하고, 페이지를 휴지통으로 보낼 수도 있습니다.

그리고 페이지의 버전 기록을 보고 두 버전을 비교하거나 예전 버전으로 되돌릴 수 있습니다. 되돌리기 직전 내용은 새 버전으로 남기 때문에 되돌린 것도 다시 되돌릴 수 있습니다. 휴지통에 뭐가 있는지 보고 페이지를 꺼낼 수도 있고, 첨부 파일도 엽니다. 이미지와 텍스트 파일, PDF의 글자(스캔한 PDF는 빼고)는 내용까지 보고, 나머지 파일은 이름과 크기만 봅니다. 워크스페이스에서 막지 않았다면 자기가 만든 이미지나 PDF, 텍스트 파일을 고칠 수 있는 페이지에 첨부할 수도 있습니다(기본 5MB까지). 필기는 워크스페이스에서 허락했을 때만 봅니다.

반대로 다른 사람의 개인 페이지나 내가 속하지 않은 워크스페이스는 볼 수 없습니다. 영구 삭제 도구는 일부러 만들지 않아서, AI가 지운 페이지는 언제나 휴지통에 남습니다. 휴지통을 비우는 것도 못 합니다. 제안을 수락하거나 거절하는 것도 사람만 할 수 있습니다. 편집 잠금이나 멤버, 공개 링크, 관리자 설정도 바꾸지 못하고, 잠금이 허락하지 않는 페이지는 고치지 못합니다.

경유 표시

AI가 한 일은 '내 이름 (앱 이름 경유)' 형태로 기록됩니다. 예를 들어 "김철수 (Claude 경유)"처럼 버전 히스토리와 코멘트, 활동 화면에 남습니다. AI가 만든 페이지에는 'AI가 작성 (… 경유)'이, AI가 고친 페이지에는 마지막 AI 편집 시각이 표시되고, AI가 페이지 전체를 바꾸기 전에는 'AI 편집 전' 스냅샷이 자동으로 저장되기 때문에 언제든 되돌릴 수 있습니다.

연결 관리

연결한 앱 목록은 설정의 '연결 관리'나 ⌘P 팔레트의 'MCP 연결 관리'에서 볼 수 있습니다. '연결 해제'를 누르면 그 앱의 접근이 바로 끊깁니다. 워크스페이스 소유자와 관리자는 워크스페이스 설정 › 연결된 에이전트에서 멤버들이 연결한 에이전트를 보고, 그 워크스페이스에서만 막을 수도 있습니다.

같은 목록에서 에이전트마다 이 워크스페이스에서 몇 번 호출했는지, 돌려받은 글이 대략 몇 토큰인지, 몇 번 실패했는지, 캐시에서 바로 답한 게 몇 번인지도 볼 수 있습니다. 숫자는 서버가 마지막으로 켜진 뒤부터 셉니다. 숫자만 남기고, 무엇을 묻고 받았는지는 저장하지 않습니다. 서버 관리자는 관리자 › 서버 상태에서 모든 에이전트 연결과 API 토큰의 숫자를 한 번에 볼 수 있습니다.

같은 질문을 여러 에이전트가 되풀이해도 서버가 앞의 결과를 기억해 두었다가 바로 돌려줍니다. 그 사이에 문서를 고치거나 권한이 바뀌면 다시 찾습니다. 다른 사람의 결과를 나눠 쓰지는 않습니다.

노트가 바뀌는 걸 계속 따라가는 에이전트라면 changes_since를 부를 때 wait를 붙이라고 알려 주세요. 몇 초마다 다시 묻는 대신 다음 변경이 생길 때까지 기다렸다가 바로 받아 갑니다.

AI 에이전트에게는 페이지 내용을 지시가 아닌 데이터로 표시해서 넘깁니다. 이 표시는 에이전트가 노트 내용과 자기가 받은 지시를 구분하는 데 도움을 줄 뿐이고, 교묘하게 쓴 페이지가 에이전트를 속이는 것까지 막지는 못합니다. 에이전트가 할 수 있는 일은 연결할 때 고르는 읽기 전용 권한과 범위, 에이전트를 제안·코멘트·읽기만으로 묶는 편집 잠금으로 정해 두시고, 잘못 고친 내용은 버전 기록에서 되돌리시면 됩니다. AI를 속이려는 것처럼 보이는 문구가 있는 페이지에는 '프롬프트 인젝션 의심 텍스트' 표시가 붙는데, 잘못 잡히는 경우도 있고 못 잡는 경우도 있습니다.

이런 글(페이지든 첨부 파일이든)을 읽은 에이전트는 한 시간 동안 제안만 할 수 있습니다. 편집은 사람의 검토를 기다리고 다른 변경은 거절됩니다. 그동안 연결 목록에는 'HH:MM까지 제안만'이 붙고, '편집 다시 허용'을 누르면 바로 풀립니다. 워크스페이스 소유자와 관리자는 워크스페이스 설정 › 연결된 에이전트 › '의심 텍스트'에서 이 기능을 끌 수 있습니다.

같은 곳의 '파일 업로드'에서는 AI 에이전트가 이 워크스페이스에 파일을 첨부할 수 있는지(서버 기본값, 켬, 끔)를 정합니다. 사람이 올리는 파일에는 영향이 없습니다.

더 자세한 내용은 MCP.ko.md를 참고하시기 바랍니다.

의미로 찾기 (서버 관리자)

AI는 기본적으로 낱말이 겹치는 섹션을 찾습니다. 서버 관리자가 의미 검색을 켜 두면 질문과 다른 말로 쓴 섹션도 찾고, 한국어로 물어도 영어로 쓴 페이지를 찾을 수 있습니다. 서버의 .env에 EMBEDDING_URL(OpenAI 호환 임베딩 API 주소입니다. 같은 네트워크의 Ollama라면 http://host:11434/v1 같은 모양입니다)과 EMBEDDING_MODEL을 넣고 서버를 다시 시작하면 됩니다. 켜 두면 서버가 노트 내용을 그 서비스로 보내서 색인을 만들기 때문에, 노트가 밖으로 나가면 안 되는 곳이라면 내부 네트워크에서 돌리는 모델 서버를 쓰시는 게 좋습니다. 색인이 얼마나 진행됐는지와 마지막 오류는 관리자 › 서버 상태에서 볼 수 있습니다. 끄려면 두 값을 지우고 다시 시작하시면 됩니다. 자세한 설정은 OPERATIONS.ko.md의 5절을 참고하시기 바랍니다.

에이전트 제안 검토하기

에이전트가 바로 고치지 않고 제안만 남기게 할 수 있습니다. 에이전트에게 그렇게 하라고 하거나, 워크스페이스를 아래처럼 검토하는 방식으로 두거나, 페이지를 '제안만'으로 잠그면 됩니다(페이지 메뉴 › 편집 잠금). 제안이 있으면 페이지 위에 몇 개가 기다리는지 한 줄로 나오고, 해당 섹션 제목 옆에 '✎ 제안 N' 표시가 붙습니다. '검토'를 누르면 제안마다 지금 내용과의 차이가 보입니다. '수락'하면 내 이름으로 적용되고 '거절'하면 버려집니다. 어느 쪽이든 제안한 에이전트는 inbox에서 결과를 받습니다. 에이전트가 읽은 뒤에 누가 그 섹션을 고쳤으면 그렇다고 알려 주고, '그래도 수락'으로 한 번 더 확인을 받습니다. 수락과 거절은 그 페이지를 고칠 수 있는 사람만 할 수 있고, 새 제안이 생기면 페이지 담당자에게 알림이 갑니다.

섹션을 통째로 바꾸는 제안은 일부만 받을 수도 있습니다. '검토'를 열면 블록 단위 변경으로 번호가 붙어 나오고, 체크한 변경만 '선택한 것만 적용'으로 들어갑니다. '사람 편집과 겹침' 표시가 붙은 변경은 에이전트가 읽은 뒤 누가 고친 블록을 건드리는 것이라 체크가 풀려 있고, 지금 내용이 같이 보입니다. 체크하면 그 자리는 에이전트 내용으로 바뀝니다. 나머지 사람 편집은 그대로 남습니다.

에이전트가 어떤 섹션을 작업하는 동안에는 제목 옆에 "Claude이(가) 이 섹션을 작업 중"이라고 나옵니다. 사람은 그대로 편집할 수 있고, 다른 에이전트만 끝날 때까지 기다립니다.

에이전트 편집 방식

워크스페이스 소유자와 관리자는 워크스페이스 설정 › 연결된 에이전트 › '에이전트 편집 방식'에서 에이전트가 페이지 본문을 어떻게 고칠지 정할 수 있습니다.

'바로 편집'이 기본값입니다. 에이전트가 사람과 똑같이 고치고, 고친 내용은 모두 페이지 기록에 남습니다.

'규칙으로 자동 수락'을 고르면 에이전트 편집은 제안이 되고, 규칙에 맞는 것은 바로 수락됩니다. 기본 규칙은 섹션 끝에 추가, 새 섹션, 제목 아래 추가이고 모든 연결이 대상입니다. 섹션 바꾸기나 삭제를 허용하거나, 특정 연결만 고르거나, 크기를 제한하거나, 사람이 먼저 거절할 수 있게 몇 분 기다리게 할 수도 있습니다. 규칙과 상관없이 에이전트가 읽은 그대로 섹션이 남아 있을 때만 수락하고, 그사이 누가 고쳤으면 사람이 정합니다. 페이지 전체를 바꾸는 편집은 항상 사람이 봅니다. 규칙으로 수락된 편집은 제안 기록에 '규칙으로 수락'이라고 남고, 페이지 기록과 활동에도 자동 수락으로 표시됩니다.

'전부 검토'를 고르면 에이전트 편집은 모두 사람이 봅니다.

잠긴 페이지나 폴더는 편집 잠금 창에서 따로 정할 수 있습니다. 이 설정은 본문 편집에만 적용되고, 페이지 이름 바꾸기나 옮기기, 휴지통으로 보내기는 지금처럼 잠금 설정을 따릅니다.

에이전트 편집 되돌리기

'활동' 화면이나 페이지 오른쪽 패널('버전 히스토리' 안의 '최근 변경')에서 에이전트가 한 변경에 '되돌리기'가 있습니다. 그 변경만, 그 에이전트가 이 페이지에서 바꾼 것 전부, 또는 워크스페이스 전체(소유자와 관리자만) 중에서 고르고 기간을 정합니다. 미리보기에 되돌릴 것과, 뒤에 누가 고쳐서 그대로 둘 것이 나옵니다. 되돌리기는 내 변경으로 기록되고('되돌리기 전' 버전이 남습니다) '되돌리기 취소'로 다시 돌릴 수 있습니다.

팀 에이전트

활동 화면 머리글의 '팀 에이전트'를 누르면 사람마다 붙인 AI 연결이 지금 무엇을 하는지 볼 수 있습니다. 잡아 둔 섹션과 남은 시간, 사람을 기다리는 제안, 오늘 한 일이 나오고, 내가 열 수 없는 페이지는 제목 없이 나옵니다.

일을 사람 대신 그 사람의 에이전트에게 넘길 수도 있습니다. 코멘트나 할 일에서 @를 치고 '민수 · Claude Code'처럼 사람 이름 뒤에 앱 이름이 붙은 항목을 고르면 그 에이전트의 inbox로만 갑니다. 민수의 다른 에이전트나 민수의 알림 종에는 가지 않습니다. 데이터베이스에서는 사람 칸을 열고 사람 이름 아래 '이 사람의 에이전트에게'에서 에이전트를 고르면 됩니다. 칸에는 사람이 그대로 남고 에이전트가 옆에 표시됩니다. 내 에이전트에게 넘어온 일을 나도 보고 싶으면 설정 › 알림에서 '내 에이전트에게 넘긴 일도 나에게 보이기'를 켜면 됩니다.

에이전트 연결을 끊거나 연결이 만료되면 그 에이전트에게 넘어갔던 일은 원래 사람에게 돌아갑니다. 일을 넘겨받았다고 에이전트에게 권한이 더 생기지는 않고, 에이전트는 여전히 연결한 사람의 권한으로만 움직입니다.

의심 텍스트를 읽은 에이전트는 여기에도 'HH:MM까지 제안만'으로 나옵니다. 그 글이 이 워크스페이스에 있었다면 워크스페이스 소유자와 관리자(그리고 그 에이전트를 연결한 사람)가 '여기서 편집 다시 허용'으로 풀 수 있습니다.

스크립트용 API 토큰

스크립트나 inklingctl에서 쓸 때는 같은 화면의 'API 토큰'에서 '새 토큰'을 누릅니다. 이름과 만료(30일, 90일, 365일, 만료 없음), 읽기 전용인지 읽기와 쓰기인지, 그리고 위와 같은 범위를 고르면 토큰이 만들어집니다. 토큰은 만든 직후 한 번만 보이니 그때 복사해 두셔야 합니다. 요청에는 Authorization: Bearer ink_pat_… 헤더로 붙이면 됩니다.

curl -H "Authorization: Bearer $INKLING_TOKEN" https://notes.example.com/api/workspaces

토큰은 고른 범위 안에서 나로서 동작합니다. 토큰과 연결 관리, 비밀번호, 2단계 인증, 멤버, 공개 링크, 웹훅, 관리자 설정은 토큰으로 바꿀 수 없고 로그인한 웹 화면에서만 됩니다. 목록에는 토큰마다 마지막으로 쓴 시각과 주소가 나오고, '폐기'를 누르면 바로 막힙니다. 비밀번호를 바꾸거나 재설정하면 AI 앱 연결과 마찬가지로 토큰도 모두 폐기됩니다. 2단계 인증을 요구하는 워크스페이스에서는 내 계정에 2단계 인증이 없으면 토큰도 거절됩니다. 서버 관리자는 관리자 › 사용자에서 멤버의 토큰을 폐기할 수 있습니다.

웹에서 저장하기

컴퓨터에서는 설정 › 연결 › 웹 클리퍼에서 "Inkling에 저장" 버튼을 북마크바로 끌어다 놓으면 됩니다. 저장하고 싶은 페이지에서 필요한 부분을 선택하고 그 북마크를 누르면, 제목과 주소, 선택한 텍스트가 채워진 작은 창이 열립니다. 저장할 워크스페이스와 위치를 고르고(마지막에 쓴 곳을 기억하고, 기본 위치를 정해 둘 수도 있습니다) 태그를 붙인 뒤 '링크와 메모'나 '본문 가져오기'를 골라 저장합니다. '본문 가져오기'는 서버가 그 페이지를 받아 본문만 남겨 둡니다. 같은 주소를 전에 저장한 적이 있으면 창에서 알려 줍니다. 북마클릿을 막아 둔 사이트도 있는데, 그럴 때는 앱에서 /clip을 열고 주소를 붙여 넣으시면 됩니다.

안드로이드 휴대폰에서는 Inkling을 앱으로 설치한 다음, 다른 앱에서 링크를 Inkling으로 공유하시면 같은 창이 열립니다. 이 부분은 실제 안드로이드 기기에서는 아직 확인하지 못했습니다.

노션에서 가져오기

노션에서 쓰던 페이지는 노션의 내보내기 파일로 옮겨 올 수 있습니다.

  1. 노션에서 설정 › 내보내기(페이지 하나라면 페이지의 ⋯ › 내보내기)를 열고 Markdown & CSV를 고릅니다. 하위 페이지 포함과 하위 페이지용 폴더 만들기를 켜 주세요.
  2. Inkling의 워크스페이스 메뉴에서 'Notion에서 가져오기 (.zip)'를 누르고 '.zip 선택'으로 받은 파일을 그대로 올리시면 됩니다.

페이지는 문서로, CSV 데이터베이스는 데이터베이스로 들어오고, 이미지와 파일은 첨부로 올라갑니다. 수식은 수식으로 옮겨지지만 콜아웃은 아직 인용으로 바뀝니다. 다 끝나면 몇 개를 가져왔고 어떤 링크를 찾지 못했는지 보고서로 보여 줍니다.

노션이 아닌 마크다운 파일은 같은 메뉴의 '가져오기 (.md/.zip)'로, .md 파일이 든 폴더는 '폴더 가져오기'로 올리시면 됩니다.

내보내기

페이지 하나는 ⋯ 메뉴에서 '내보내기 (.md)'로, 하위 페이지까지 함께 받으시려면 '하위 포함 내보내기 (.zip)'로 받습니다. 캔버스는 .canvas 파일로 나옵니다. 차트, 데이터베이스 보기, 쿼리 블록은 내보낼 때의 숫자를 표로 같이 적어 두고, 그 파일을 다시 가져오면 블록으로 돌아옵니다. PDF가 필요하시면 페이지 머리글 ⋯ 메뉴의 'PDF로 내보내기'를 누르시면 됩니다. 브라우저의 인쇄 창이 열리는데, 열이 많은 표는 페이지 폭에 맞춰 줄어들고(열이 7개 이상이면 글자가 작아집니다. 아주 넓은 표는 인쇄 창에서 가로 방향을 고르세요), 닫아 둔 토글도 펼쳐서 찍히며, 다크 테마에서도 밝은 색으로 찍힙니다. 데이터베이스는 '현재 뷰를 CSV로 내보내기'와 '현재 뷰를 Excel로 내보내기'를 씁니다.

워크스페이스 전체는 워크스페이스 메뉴의 '전체 내보내기 (.zip)'로 받을 수 있는데, 소유자가 이 권한을 일부에게만 열어 두었을 수도 있습니다. ⋯ 메뉴의 '노션으로 보내기'는 서버에 노션 연동이 설정된 경우에만 동작합니다.

긴 페이지 나누기

실험 기록이나 일지처럼 계속 길어지는 페이지는 열고 저장하고 검색하는 데 점점 시간이 걸립니다. 페이지 머리글 ⋯ 메뉴의 '페이지 나누기…'를 누르면 제목을 기준으로 페이지를 나눌 수 있습니다. H1, H2, H3 가운데 나눌 제목을 고르고, 이 페이지에 남겨 둘 부분은 체크를 풀어 주세요. 체크된 제목마다 그 아래 내용과 함께 하위 페이지가 됩니다. 원래 페이지에는 나간 부분 자리에 하위 페이지 링크가 남고, 나누기 전 상태는 버전 히스토리에 저장됩니다. 댓글은 블록을 따라 옮겨 가고, 이 페이지로 걸린 링크도 그대로 동작합니다. 다른 사람이 페이지를 열어 둔 상태여도 그 화면에서 바로 바뀝니다.

같은 창 아래쪽의 '새 기록'은 AI 에이전트나 API가 덧붙이는 내용이 들어갈 곳을 정합니다. 기본값은 이 페이지에 계속 쓰는 것이고, '달마다 하위 페이지'를 고르면 2026-11 같은 하위 페이지에, 크기를 고르면 지금 쓰는 하위 페이지가 그 크기를 넘을 때마다 새 하위 페이지에 이어 씁니다. 페이지에서 직접 입력하는 것은 바뀌지 않습니다.

내 페이지가 커졌는데도 무언가가 계속 덧붙이고 있으면 알림이 한 번 옵니다. 같은 페이지로는 다시 오지 않습니다.

휴지통과 버전 히스토리

페이지를 지우면 사이드바 아래쪽의 휴지통으로 갑니다. 휴지통을 열어 '복원'하거나 '영구 삭제'할 수 있습니다. 휴지통은 기본으로 30일 동안 보관하는데, 소유자가 워크스페이스 설정 › 일반 › 휴지통 보관 기간에서 바꿨을 수도 있습니다. 서버가 더 짧은 상한을 정해 두었다면 그 설정에 상한이 나오고 더 큰 값은 받지 않습니다. 지울 때마다 묻는 게 번거로우시면 설정 › 파일 · 링크 › 삭제 전 확인을 끄시면 됩니다. 그러면 확인 없이 휴지통으로 보내고 대신 되돌리기 알림을 띄웁니다.

글을 예전 상태로 돌리고 싶을 때는 오른쪽 패널의 버전 히스토리를 봅니다. '전체 보기'를 누르면 같은 이름의 창이 열리고, 여기서 버전을 미리 보거나 '현재와 비교'로 바뀐 곳을 확인할 수 있습니다. 중요한 시점에는 '지금 스냅샷'으로 직접 저장해 두셔도 되고, '이 버전으로 복원'을 누르면 복원하기 전의 상태도 먼저 저장해 둡니다.

AI 에이전트가 고친 내용은 쓸 때마다 'AI 편집 · n단계'라는 버전으로 하나씩 남고, 어느 섹션을 몇 줄 바꿨는지도 같이 보입니다. 잘못된 단계 바로 앞 단계로 복원하면 그 부분만 되돌릴 수 있고, 뒤의 단계들은 목록에 그대로 남습니다.

워크스페이스를 통째로 지운 경우에는 소유자가 30일 안에 설정 › 계정 › 삭제한 워크스페이스에서 되살릴 수 있습니다(서버가 다른 일수를 정할 수 있고, 화면에 그 일수가 나옵니다). 옆의 '지금 완전히 삭제'를 누르면 페이지와 파일까지 바로 지워지고, 그 뒤에는 되살릴 수 없습니다.

설정과 사이드바

설정은 ⌘,를 누르거나 사이드바 아래쪽의 '설정'으로 엽니다. 왼쪽에는 계정, 보안, 알림, 편집기, 사이드바, 파일 · 링크, 모양, 연결, 단축키, 오프라인, 정보 분류가 있고, 하나를 고르면 오른쪽에 그 설정이 나옵니다. 휴대폰에서는 분류 목록이 먼저 나오고, 분류를 누르면 그 화면으로 들어갑니다. 2단계 인증은 보안에, 앱 버전과 사용 설명서 링크, 소개 다시 보기와 시작하기 체크리스트는 정보에 있습니다.

설정 화면의 항목은 저장되는 곳이 두 가지로 나뉩니다. 계정, 보안, 알림, 사이드바, 캘린더 구독 (iCal), 그리고 모양 안에 있는 언어는 계정에 저장되기 때문에 어느 기기에서 열어도 같습니다. 반면 편집기(본문 폭, 맞춤법 검사, 단어 수 표시, 오른쪽 목차), 파일 · 링크(앱 시작 시 열 페이지, 새 페이지 위치, 링크 미리보기, 삭제 전 확인), 모양의 테마와 배율은 지금 쓰는 기기의 브라우저에만 저장됩니다. 이런 항목에는 이름 옆에 '이 기기'라고 작게 표시해 두었습니다. 맥과 태블릿에서 글씨 크기를 다르게 두고 싶은 경우가 많아서 이렇게 나눴습니다.

설정 › 계정의 '계정 삭제'는 먼저 지워지는 것을 보여 줍니다. 나만 멤버인 워크스페이스와 내가 혼자 소유한 삭제된 워크스페이스, 그 페이지·파일, 다른 워크스페이스에 있는 내 개인 페이지, 계정, 로그인 기록, 토큰, 연결된 앱입니다. 다른 멤버를 위해 남는 것도 보여 줍니다. 내가 혼자 소유한 공유 워크스페이스는 다른 멤버에게 넘어가고, 내가 쓴 공유 페이지와 코멘트는 이름 없이 남습니다. 화면에 나오는 확인 문구(내 이메일이나 아이디)와 비밀번호를 넣고, 2단계 인증을 켜 두셨다면 그 코드도 넣습니다. 다른 서비스로 로그인하는 계정은 로그인한 지 10분 안이어야 합니다. 되돌릴 수 없고, 복구용으로 남겨 두는 것도 없습니다. 서버의 유일한 관리자는 계정을 삭제할 수 없습니다.

사이드바 메뉴

사이드바 위쪽에 나오는 검색, 나중에 보기, 스레드, 그래프, 태그, 웹 공유, 마감, 캘린더, 활동, 오늘 메뉴는 설정 › 사이드바에서 숨기거나 순서를 바꿀 수 있습니다. 끌어서 옮기셔도 되고 ↑/↓ 버튼을 쓰셔도 됩니다. ↑/↓ 버튼은 그 줄에 마우스를 올리거나 키보드로 고르면 나타납니다. 한 번도 손대지 않았다면 검색, 나중에 보기, 마감, 캘린더만 보이고, '기본값으로 되돌리기'를 누르면 이 네 개로 돌아갑니다. 사이드바에서 메뉴를 우클릭(휴대폰에서는 길게 누르기)하고 '사이드바에서 숨기기'를 골라도 같습니다. 숨긴 메뉴도 ⌘P 팔레트나 단축키로는 그대로 열립니다.

사이드바 전체를 접고 펴는 단축키는 ⌘\입니다. 사이드바 폭은 오른쪽 끝을 끌어서 200~480px 사이로 바꿀 수 있고, 끝을 더블클릭하면 기본값인 260px로 돌아갑니다. 키보드로 끝에 초점을 둔 다음 ←/→를 눌러도 되고, Shift를 같이 누르면 더 크게 움직입니다. 폭은 본문 폭처럼 지금 쓰는 기기에만 저장됩니다. 휴대폰에서 여는 사이드바는 그대로입니다.

화면이 낮아서 메뉴가 다 들어가지 않으면 페이지 목록 자리를 먼저 남겨 두고, 남는 메뉴는 '더보기 (n)' 아래로 접힙니다. '더보기'를 누르면 접혀 있던 n개가 전부 보이고(그동안 페이지 목록이 조금 줄어듭니다), '접기'를 누르면 다시 접힙니다. 창이 아주 낮으면 펼친 목록이 스크롤되고 맨 아래에 '아래에 k개 더'가 나옵니다. 펼쳐 둔 상태는 기기마다 따로 기억합니다. 태블릿을 가로로 두거나 앱 안 브라우저로 열어서 높이가 많이 모자랄 때는 휴지통, 단축키, 설정, 계정이 아래쪽에 아이콘 한 줄로 줄어듭니다.

단축키

글을 입력하는 중이 아닐 때 ?를 누르면 앱 안에서 단축키 목록을 볼 수 있습니다. 키가 동작하는 곳(전역, 페이지, 에디터, 사이드바 트리, 표, 필기 모드)별로 나뉘어 있고, 위의 검색 칸에 이름이나 키를 넣으면 맞는 것만 남습니다. 한글 이름, 영어 이름, 초성(ㄱㄹㅍ), 키(⌘⌥) 어느 것으로 찾아도 됩니다. 설정 › 단축키에도 같은 목록이 있고, 거기서 키를 바꿀 수 있습니다.

키를 바꾸려면 설정 › 단축키에서 바꿀 명령의 키를 누르고 새로 쓸 조합을 누르면 됩니다. 도중에 Esc를 누르면 아무것도 바뀌지 않고, '키 없음'을 누르면 그 명령에서 키를 뺍니다. 새 키에는 ⌘, ⌥, ⌃ 중 하나가 들어가야 합니다(윈도우와 리눅스에서는 Ctrl이나 Alt). F1~F12는 혼자 써도 되고, 사이드바 트리와 표에서는 화살표, Enter, Tab, Space도 혼자 쓸 수 있습니다. ⌘W, ⌘Q, ⌘Tab, 개발자 도구 키처럼 운영체제나 브라우저가 먼저 가져가서 페이지까지 오지 않는 키와 ⌘A/⌘C/⌘X/⌘V는 받지 않습니다.

다른 명령이 이미 쓰고 있는 키를 누르면 어느 명령인지 알려 주고, '여기에 쓰기'를 눌러야 키가 옮겨 옵니다. 브라우저 탭이 먼저 가져가는 키(⌘N, ⌘⇧N)나 브라우저 기능 키(⌘F 찾기, ⌘R 새로고침, 확대·축소)는 경고를 보고 '그래도 쓰기'를 누르면 쓸 수 있습니다. '오늘 (데일리 노트)', '나중에 보기', '스레드', '이 페이지 나중에 보기에 저장'처럼 원래 키가 없는 명령에도 키를 붙일 수 있습니다. 굵게, 기울임, 제목, 목록, 블록 옮기기, 실행 취소처럼 편집기에 들어 있는 키와 표의 복사·붙여넣기는 '고정'으로 표시되고 바꿀 수 없습니다.

바꾼 키는 바로 적용됩니다. 열려 있는 페이지와 편집기에서도 다시 열 필요 없이 새 키로 동작하고, ? 창과 팔레트, 메뉴에도 새 키가 나옵니다. '기본값'은 그 명령 하나를, '전체 초기화'는 모든 명령을 처음 키로 돌립니다. 바꾼 키는 지금 쓰는 브라우저에만 저장됩니다. 다른 기기에서도 같은 키를 쓰고 싶으면 '내보내기'로 JSON 파일을 받아서 그 기기에서 '가져오기'로 올리시면 됩니다. 두 명령이 같은 키를 쓰게 되는 파일은 가져오지 않습니다.

⌘P를 누르면 명령 팔레트가 열립니다. 지금 화면에서 쓸 수 있는 명령이 단축키와 같이 나오고, 글자를 넣으면 제목이 맞는 페이지도 같이 나옵니다. 명령마다 한글 이름과 영어 이름을 둘 다 찾기 때문에 "사이드바", "sidebar", "ㅅㅇㄷ" 어느 것을 넣어도 '사이드바 접기/펼치기'가 나옵니다. 검색 칸이 비어 있으면 최근에 실행한 명령이 맨 위에 옵니다. ↑/↓로 고르고 Enter로 실행하며 Esc로 닫습니다. 제목 단계 바꾸기, 블록 옮기기, 블록 복제 같은 에디터 명령은 팔레트를 열기 전에 커서가 있던 블록에 적용됩니다. 페이지 ⋯ 메뉴, 사이드바 트리의 줄 메뉴, 사이드바 메뉴에도 단축키가 있는 항목은 오른쪽에 키가 같이 나옵니다.

일반 브라우저 탭에서는 ⌘N을 브라우저가 새 창 열기로 가져가서 ⌘⌥N을 쓰셔야 합니다. 설치한 앱(PWA)에서는 둘 다 됩니다. 맥 크롬에서는 ⌘⌥←/→가 브라우저 탭 이동이라서, 탭에서는 브라우저의 ⌘[ / ⌘]로 뒤로·앞으로 가시면 됩니다. 설치한 앱에서는 ⌘⌥←/→가 그대로 됩니다. 한글을 조합하는 중에는 단축키가 동작하지 않고 글자가 다 만들어진 다음부터 동작합니다. 윈도우에서 키보드 배열이 Ctrl+Alt(AltGr)로 글자를 입력하는 경우에는 단축키 대신 그 글자가 입력됩니다.

휴대폰과 태블릿

따로 설치할 앱은 없고 브라우저에서 바로 쓰시면 됩니다. 앱처럼 쓰고 싶으시면 브라우저로 서버 주소를 연 다음 브라우저 메뉴의 설치 또는 홈 화면에 추가를 고르시면 됩니다(PWA). 이렇게 설치하면 주소창 없이 따로 열립니다.

페이지 머리글에는 즐겨찾기, 웹에 공유, 접속 중인 사람, 오른쪽 패널, ⋯만 있고 필기 모드, 편집 잠금, 페이지 알림, PDF, 테마는 ⋯ 메뉴 안에 있습니다(⋯에 점이 보이면 잠금이 걸렸거나 팔로우 중인 페이지입니다). 화면이 좁을 때는 웹에 공유와 오른쪽 패널도 ⋯ 안으로 들어갑니다.

오프라인에서 쓰기

설정 › 오프라인에서 '이 기기에 오프라인 사본 보관'을 켜세요(설치한 앱에서는 처음부터 켜져 있고, 브라우저 탭에서는 꺼져 있습니다). 그다음부터 연 페이지는 이 기기에 보관되어, 연결이 없어도 앱이 뜨고 마지막에 본 페이지 목록과 그 페이지들을 읽고 고칠 수 있습니다. 오프라인이면 위에 안내 줄이 보이고, 편집이 기기에서 기다리는 동안 페이지 옆 점에 '아직 올라가지 않음'이 나옵니다. 다시 연결되면 편집이 올라가고 '오프라인 편집을 올렸습니다'가 뜹니다. 그사이 누가 이 페이지를 이전 버전으로 복원했거나 되돌리기·나누기를 했거나, 휴지통으로 옮겼거나, 내 편집 권한을 없앴다면 오프라인 편집은 섞이지 않고 설정 › 오프라인 › 복구 항목에 따로 남습니다. 거기서 내용을 보고 필요한 부분을 옮기시면 됩니다. 오프라인에서는 페이지를 새로 만들거나 옮기고 지우는 일, 데이터베이스와 첨부 파일, 캔버스, 검색은 안 됩니다. 브라우저 저장소가 응답하지 않으면 '연결 중…'에서 기다리지 않고 5초쯤 뒤에 서버에서 페이지를 엽니다. 그 탭은 새로 고칠 때까지 기기에 사본을 남기지 않습니다. 로그아웃하면 기기에 보관된 것은 모두 지워집니다. 사본은 암호화되지 않으니 여러 사람이 같이 쓰는 컴퓨터에서는 꺼 두세요.

자주 묻는 질문

내 페이지는 누가 볼 수 있나요?

공유 구역의 페이지는 워크스페이스 멤버 모두가 봅니다. 개인 구역의 페이지는 본인과, 본인이 연결한 AI 앱만 볼 수 있습니다.

읽기만 하는 멤버를 둘 수 있나요?

페이지 공유 창에서 그 멤버에게 '볼 수 있음'을 주시면 그 페이지와 하위 페이지는 읽기만 할 수 있습니다. 자세한 내용은 페이지별 권한과 게스트를 보시면 됩니다. 편집 잠금이나 웹 공유 링크도 전처럼 쓸 수 있습니다.

외주 디자이너에게 한 페이지만 고치게 할 수 있나요?

그 페이지 공유 창에서 디자이너의 이메일 주소를 넣고 '편집 가능'으로 초대하시면 됩니다. 디자이너에게는 그 페이지와 하위 페이지만 보입니다.

페이지를 실수로 지웠어요.

사이드바 아래쪽의 휴지통을 열고 '복원'을 누르시면 됩니다. 페이지는 그대로 있는데 내용을 예전으로 돌리고 싶으신 거라면 오른쪽 패널의 버전 히스토리를 쓰시면 됩니다.

누가 내 페이지를 고쳤는지 알고 싶어요.

오른쪽 패널의 버전 히스토리나 활동 화면에서 누가 무엇을 바꿨는지 볼 수 있습니다. AI가 고친 경우에는 '경유'가 붙어 있어서 구분됩니다.

AI 앱이 페이지가 잠겨 있다고 해요.

편집 잠금이 에이전트의 편집을 막고 있는 상태입니다. 페이지 담당자나 워크스페이스 관리자에게 잠금 설정을 바꿔 달라고 요청하셔야 합니다.

알림 메일이 오지 않아요.

설정 › 알림을 먼저 확인해 보시기 바랍니다. 서버에 메일 설정이 없다는 안내가 나온다면, 그 서버에서는 알림을 앱 안에서만 볼 수 있습니다.

"이 화면을 표시하지 못했습니다"라고 나와요.

화면을 그리다가 문제가 생긴 경우입니다. '새로고침'을 누르시면 대개 해결됩니다. 한 페이지만 계속 안 열리면 사이드바는 그대로 쓸 수 있으니 다른 페이지로 옮겨 가셔도 됩니다. 알려 주실 때는 '자세히' 아래에 나오는 글을 같이 보내 주시면 원인을 찾기 쉽습니다. 앱이 아예 뜨지 않을 때는 12초쯤 뒤에 새로고침 링크가 있는 안내가 나옵니다.

워크스페이스에서 나가고 싶어요.

워크스페이스 설정 › 위험 구역에서 '워크스페이스 나가기'를 누르시면 됩니다. 그 워크스페이스에 있던 개인 페이지는 휴지통으로 갑니다. 본인이 유일한 소유자이고 다른 멤버가 있다면 소유권을 먼저 넘기셔야 나갈 수 있습니다. 본인이 유일한 멤버라면 나갈 때 워크스페이스가 페이지와 파일까지 지워지고 되돌릴 수 없습니다. 이름을 입력하고 '나가고 삭제'를 누르거나, 대신 '삭제하고 N일 동안 복구 가능하게 두기'를 고르시면 됩니다.
