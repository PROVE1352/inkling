# 1190. Generic webhooks: signed JSON to any public https endpoint

- Status: Accepted
- Date: 2026-11-07
- Amends: [0504](0504-workspace-webhooks.md) (URL policy, kinds), [1111](1111-webhook-and-sheet-urls-sealed-at-rest.md) (one more sealed column)

## Context
Workspace webhooks (ADR 0504) post a one-line chat message to Slack or Discord only: the host is on an
allowlist and the body is chat markup. People who automate with n8n, Zapier, Make or their own server
need structured events, and a receiver on the open internet needs to know that a request came from
this Inkling and was not replayed. Delivery already runs through the outbox with a stable
`X-Inkling-Delivery` id (ADR 1081, 1150).

## Decision
**Kind `generic`, chosen explicitly.** `workspace_webhooks.kind` gains `generic` (the column is plain
`text`, no SQL constraint). The create route takes `kind: 'generic'`; a URL is never inferred to be
generic, so a mistyped Slack URL is refused instead of silently becoming a signed JSON hook.

**URL policy (SSRF).** https, port 443 only, no credentials, no fragment; a query string is kept
(some receivers route on it). Checked when saved: `safeFetch.validateUrl` (scheme, port, literal
private / loopback / link-local / metadata addresses, `localhost`) and `resolvePublic` (every DNS answer
must be public; an unresolvable host is refused). Checked again on every delivery by `safeFetch` without
a host allowlist: DNS resolved and checked, the socket pinned to the checked address, `maxRedirects: 0`
(a 3xx is a non-retryable failure, "redirects are not followed"), 3 s connect / 8 s total, 16 KiB read
then the socket is closed. The loopback test mode (`WEBHOOK_TEST_ALLOW_LOOPBACK=1`, ignored in
production) remains the only bypass. Other ports (n8n's 5678) were rejected: the port allowlist is part
of the SSRF guard everywhere else, and self-hosted receivers sit behind a reverse proxy on 443 anyway.

**Body: versioned JSON, references not content.** `{ version: 1, id, type, occurredAt, workspace,
actor, page?, comment?, users?, field?, pages?, total?, url? }` (`WebhookPayloadV1` in
`packages/shared`, documented per event in docs/WEBHOOKS.md). `id` = the delivery id;
`occurredAt` = the outbox row's `created_at` (not the attempt time). Fields are only added within a
version.
- The event is resolved at delivery by the same function for every kind (`resolveEvent`, the old
  `buildMessage` split into "resolve" and "format"): a page that is not `scope='shared'`, deleted, or
  in another workspace drops the delivery; digests name only live shared pages. Slack and Discord
  text is produced from the same resolved event and is byte-identical to before.
- **No comment text, no page content, no e-mail addresses.** Slack and Discord keep their 140-character
  excerpt (it is the message). A generic receiver is arbitrary third-party storage (Zapier keeps task
  history), and every field sent is a field that can leak; ids, names, titles and links are enough to
  route an event, and a receiver that needs the text fetches it with a personal API token, so its
  access is that token's access and is revocable. Digests list ≤ 50 pages plus `total`.

**Signature (Stripe's scheme).** `X-Inkling-Signature: t=<unix>,v1=<hex>` where `v1` =
HMAC-SHA256(secret, `t + "." + body`) over the exact bytes sent; `t` is the attempt time, so a resend
days later still passes a 5-minute tolerance. Also `X-Inkling-Event: <type>` and the existing
`X-Inkling-Delivery`. Receivers verify over the raw body in constant time, reject `t` outside ±5 minutes
and drop already-seen delivery ids (examples in Node and Python in docs/WEBHOOKS.md, checked against
this implementation).

**Secret.** `whsec_` + 32 random bytes (base64url), generated by the server, returned **once** in the
create response (`{ webhook, secret }`) and once per rotation; the DTO only says `hasSecret`. Stored in
`workspace_webhooks.secret` like the URL (ADR 1111): sealed with `APP_SECRET_KEY` (purpose
`webhook-secret`, row id as AAD) when the key is set, plaintext otherwise, sealed by the boot pass when a
key is added later; an unreadable secret fails the delivery with a non-retryable error.
`POST /api/webhooks/:id/secret` (owners, 10/min) rotates: the old stored value moves to
`previous_secret` and is signed with for 24 h (`previous_secret_until`), so a receiver can deploy the new
secret without a gap; `{ keepPrevious: false }` revokes it at once (leaked secret). Audited as
`webhook.updated` with `after: { secret: 'rotated', previousValidUntil }`, never the value.

**Test event.** `POST /webhooks/:id/test` sends `type: "test"` with a fresh `test_<uuid>` id, signed, to
generic hooks (Slack/Discord keep their text).

**Unchanged.** Retry policy (4 attempts over ~1 minute) and the per-workspace bucket and 200-row flood
guard apply to generic hooks as they are. A longer retry window (hours, like Stripe) was rejected for
now: pending rows count toward the 200-row workspace guard, so one dead receiver retrying for hours
would start dropping the events of every other hook in the workspace. Resend (ADR 1191) covers longer
outages by hand.

## Alternatives considered
- **Signing Slack / Discord deliveries too:** they ignore the header and their URL is the secret.
- **Secret chosen by the owner:** weak secrets; a generated one costs nothing.
- **Bearer token header instead of an HMAC:** proves the sender but not the body, and a captured request
  can be replayed forever; the HMAC with a timestamp bounds replays to the tolerance window.
- **Asymmetric signatures (Ed25519, public key published by the server):** no shared secret to leak on
  the receiver's side, but every receiver tool (n8n, Zapier code steps) has HMAC helpers and few have
  Ed25519; rotation would need key ids. HMAC matches what receivers already implement for Stripe/GitHub.
- **Per-hook "include comment excerpt" switch:** possible later, without a version bump (an added field).

## Consequences
- Migration: `workspace_webhooks.secret`, `previous_secret`, `previous_secret_until` (plus ADR 1191/1192
  columns); no data migration.
- A receiver gets at-least-once delivery with a stable id (ADR 1081) and can authenticate it; the crash
  test is repeated for generic hooks (`webhooksGeneric.db.test.ts`: SIGKILL after the HTTP call →
  redelivered once, same id, both copies verify).
- Tests: URL policy outside test mode (literal private / loopback / metadata / IPv4-mapped / decimal
  IPv4 / ULA, ports, schemes, credentials, fragment), signature vectors, privacy (no comment text, no
  private page), rotation with two signatures and revocation, owner-only rotation.
