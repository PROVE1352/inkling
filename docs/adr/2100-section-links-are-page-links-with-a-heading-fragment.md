# 2100. Section links `[[Page#Heading]]` are page links with a heading fragment

- Status: Accepted
- Date: 2026-11-10

## Context
Links were page-sized: `[[Page]]` is a BlockNote `link` inline with href `/w/<ws>/p/<page>`, and
`[[Page#Heading]]` from Markdown resolved to the subpage a split made from that section (ADR 1140) or
to the page itself, with the whole `Page#Heading` as its text and no way to land on the heading.
Obsidian and Notion users link to sections all the time. The section machinery already exists
(heading-path anchors and block ids, ADR 0926; the rename trace, ADR 1501; name rules for writes,
ADR 1960), but nothing in a document could point at a section.

## Decision
- **Storage: the same `link` inline, with a fragment** (`@inkling/shared/sectionLink`):
  `/w/<ws>/p/<page>#h=<heading>&b=<heading block id>&p=<page title>`, fields in that order.
  `h` (always) is the heading text when the link was made; `b` the heading's block id when known (links
  made in the editor); `p` the page title then. The link's text is what the page shows: `Page#Heading`
  without an alias, the alias otherwise. No schema change, no new node: every reader that only knows
  page links (backlinks, graph, previews, public rewrite) keeps working because the path is unchanged.
- **Markdown** (people's export, MCP reads and writes, vault sync, Notion publish, the section index
  text): `[[p#h]]`, or `[[p#h|shown]]` when the text is not the plain target. Vault sync writes the
  page's current title instead of `p` (as it does for page links). Import: the whole text keeps its old
  meanings first (an exact title, alias or former title, and the split subpage stay page links);
  otherwise the last `#` whose left part is a page's own title wins (titles with `#`, headings with
  `#`), the resolver's own `X#Y → X` fallback not counting as a title. `[[Page|alias]]` without `#` is
  unchanged (out of scope). Imported links have no `b`.
- **Not inside code blocks**: `[[…]]` in a code block is code (Mermaid's `A[[Name]]`), so Markdown
  import no longer turns it into a link there (`mapBlockInlines(…, skip)`).
- **Editor**: `[[Page#` lists the page's section headings (`GET /pages/:id/headings`, top-level
  headings as ADR 0926 defines sections) and inserts a link with `h`, `b`, `p`.

## Alternatives considered
- **A new inline node (`sectionLink`).** Clean props, but a schema change on server and web (ADR
  1500/1539 rules: every reader must know it or y-prosemirror deletes it) and every page-link reader
  would need a second case.
- **Only the anchor (`#setup/backups`) or only the block id.** Anchors change on rename; block ids
  are regenerated by replace, import and vault upload (ADR 0926). Both, plus the text, survive more.
- **`?block=` in the href.** Already used for one-shot jumps and removed after use; a query string
  in a stored link would be stripped by the same code.
- **Link text = `Page › Heading`.** Nicer to read, but export would have to split it back; the
  Obsidian form is unambiguous and is what people type.

## Trade-offs
- The link text and `p`/`h` are a snapshot: a renamed page or heading keeps the old text in the
  document (the link still follows it, ADR 2102; vault sync writes the current page title).
- Section links reach top-level headings only (the section definition). A heading inside a toggle can
  be reached by a link with its block id in the editor, but the server treats it as missing.
