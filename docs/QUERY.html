Using Inkling

Query blocks

The Dataview subset: TABLE, LIST, TASK, FROM, WHERE, SORT, LIMIT.

Rendered from docs/QUERY.md in the repository. Markdown source

A Query block shows a live table or list of pages, written in a subset of the Obsidian Dataview query language. 한국어: QUERY.ko.md.

Insert one with / → Query. The block is a code block whose language is dataview; the results render underneath and refresh when pages in the workspace change. Because it is a plain ```dataview fence, the query survives markdown export, the MCP connector and vault sync unchanged — an Obsidian vault with the Dataview plugin runs the same query.

TABLE status, due, file.tags
FROM #project AND "Work/Clients"
WHERE status != "done" AND due < date(today)
SORT due ASC
LIMIT 50

Query shape

TABLE [WITHOUT ID] <expr> [AS "Label"], …   |   LIST [<expr>]   |   TASK
[FROM <source>]
[WHERE <expr>]
[SORT <expr> [ASC|DESC], …]
[LIMIT <n>]
  • Keywords are case-insensitive. FROM must come first; WHERE, SORT, LIMIT may appear in any order, each at most once.
  • TABLE shows a page-link column first unless WITHOUT ID is given.
  • LIST <expr> shows the value next to each page link.
  • TASK lists checklist items that carry a date (the page_tasks index — the same items the calendar and the due view show). Undated checklist items are not indexed and do not appear.

Sources (FROM)

SourceMatches
#tagpages with the tag in their text or in a tags property. Case-insensitive; #a also matches nested #a/b.
"Folder/Sub"pages anywhere below that page path (titles joined by /, as in the sidebar tree), plus the page at that exact path
[[Page]]pages that link to Page
-src, NOT srcnegation
a AND b, a OR b, ( … )combinations

Without FROM, every document page you can see in the workspace is considered.

Fields

FieldValue
file.name, file.linkpage title
file.ctime, file.mtimecreated / last modified (timestamp)
file.cday, file.mdaycreated / modified date (YYYY-MM-DD, in your time zone)
file.tagslist of #tags (text tags and the tags property)
file.folderpath of the parent (Work/Clients), "" at the root
file.pathpath of the page itself
any other namethe page property with that name (case-insensitive), else — for collection rows — the collection field with that name. Select options show their label. A person field shows the member's name and a relation field links to the rows you can see (rows you cannot see are left out) (docs/adr/1320-). WHERE and SORT use the same: a person field compares as the member's name, a relation field as the titles of the linked rows you can see (SORT uses them joined with ", "), so WHERE Owner = "Priya Nair" matches. =, != and contains() also match the stored id of a member or of a visible linked row. Names and titles match exactly, case included (docs/adr/1352-).
`Name with spaces`back-ticks quote a property name
text, due, completed / checkedTASK only: the item text, its date, its check state

Expressions

  • Literals: "text", 42, 3.5, true, false, null
  • Dates: date(today), date(tomorrow), date(yesterday), date("2026-11-07"). today is the viewer's local date.
  • Comparison: = != < <= > >=
    • field = "x" is also true when the field is a list containing "x".
    • Comparing with a number compares numerically (numeric strings count).
    • Comparing with a date compares the YYYY-MM-DD part; file.ctime / file.mtime compare against local midnight of that date.
  • contains(list, "x") — list membership, or substring for text values.
  • Boolean: AND / &&, OR / ||, NOT / !, parentheses. A bare field is true when it is set and not false, 0, "" or [].

Limits

LimitValue
query length2 000 characters, 400 tokens, nesting depth 24
columns / sort keys20 / 5
rowsLIMIT ≤ 500 (default 200); the block says when results were cut off
execution3 s statement timeout — narrow the query with FROM / WHERE if it is hit

Results only include pages you are allowed to see (shared pages and your own private pages); trashed pages and templates are excluded.

Errors

Syntax errors are shown inside the block with the line, column and a caret under the problem. The same parser runs in the browser and on the server (packages/shared/src/query.ts).

Differences from Dataview

Not supported: CALENDAR queries, GROUP BY, FLATTEN, inline fields (key:: value), arithmetic, durations (date(today) - dur(1 week)), regex functions, DataviewJS, and FROM on outgoing links (outgoing([[Page]])). TASK covers dated checklist items only.

API

POST /api/workspaces/:id/query — see API.md.
