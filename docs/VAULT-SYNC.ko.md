# 옵시디언 볼트 동기화 (실험 기능)

Markdown 노트 폴더(옵시디언 볼트 또는 그 안의 하위 폴더)와 Inkling 워크스페이스를 양방향으로 동기화합니다. English: [VAULT-SYNC.md](VAULT-SYNC.md).

> **0.17에서도 아직 실험 기능입니다.** `EXPERIMENTAL_FEATURES`에 `vault-sync`가 들어 있지 않으면 서버의 동기화 경로(route)는 꺼진 채로 있습니다.
> 0.17에서 점검하다가 찾은 데이터 손실 경로는 모두 막았지만([현황](#status-and-what-is-left) 참고), 필수 조건 두 가지를 아직 채우지 못했습니다.

**서버:** `EXPERIMENTAL_FEATURES`에 `vault-sync`를 넣으세요(예: `EXPERIMENTAL_FEATURES=vault-sync`).

```sh
inklingctl login --server https://notes.example.com
inklingctl sync ~/Vault/Inkling --workspace "Team notes"     # run it whenever you like
inklingctl sync ~/Vault/Inkling --workspace "Team notes" --dry-run
```

두 번째 줄의 주석은 동기화를 원할 때마다 실행하면 된다는 뜻입니다.

비밀번호로 로그인하는 대신 API 토큰(설정 › 연결 › API 토큰, `Settings → Connections → API tokens`)을 쓸 수도 있습니다. `inklingctl login --token`으로 로그인하거나, 한 번만 실행할 때는 `INKLING_TOKEN=ink_pat_… inklingctl sync …`처럼 씁니다. 한 페이지의 하위 트리로 범위를 제한한 토큰은 그 하위 트리만 동기화하고, 새 최상위 노트는 거절합니다. 자세한 것은 [apps/cli/README.md](../apps/cli/README.md)를 보세요.

워크스페이스마다 전용 폴더를 따로 쓰세요. 처음 실행할 때 그 폴더가 워크스페이스와 연결되고, 그 뒤로는 다른 워크스페이스를 지정하면 거절합니다.

<a id="what-happens-on-each-run"></a>
## 실행할 때마다 일어나는 일

| 상황 | 결과 |
|---|---|
| 볼트에서만 노트가 바뀜 | 업로드합니다. 그다음 파일을 Inkling의 표준 형식으로 다시 씁니다 |
| Inkling에서만 페이지가 바뀜 | 파일을 고칩니다 |
| 양쪽 다 바뀜, 서로 다른 줄 | 줄 단위로 합치고 양쪽을 모두 고칩니다 |
| 양쪽 다 바뀜, 같은 줄 | **충돌**: 내 노트는 그대로 두고, `Name (conflict 2026-11-07).md`에 두 버전을 `<<<<<<<` 표시와 함께 담습니다. 노트를 고치고 충돌 사본을 지운 다음 다시 동기화하세요 |
| 볼트에서 노트를 지움, 페이지는 그대로 | 페이지를 Inkling 휴지통으로 옮깁니다 |
| Inkling에서 페이지를 지움, 노트는 그대로 | 노트를 `.inkling/trash/<date>/`로 옮깁니다 |
| 한쪽에서 지우고 다른 쪽에서 고침 | 고친 쪽이 이깁니다(노트를 되살리거나 다시 만듭니다) |
| 파일 이름을 바꾸거나 옮김 | 페이지 이름을 바꾸거나 옮깁니다(반대 방향도 마찬가지입니다) |
| 새 노트 / 새 페이지 | 반대쪽에 만듭니다. 새 폴더는 폴더 페이지가 됩니다 |
| 하위 페이지가 있는 페이지나 폴더를 볼트에서 이름 바꾸거나 옮김 | 같은 페이지나 폴더 페이지의 이름을 바꾸거나 옮깁니다(코멘트, 잠금, 권한은 그대로 남습니다) |
| 볼트에서 폴더를 지움 | 그 안의 노트와 폴더 페이지를 휴지통으로 보냅니다(마지막으로 끝까지 마친 실행 때 노트가 들어 있던 폴더만 그렇습니다. 사본에 빠져 있는 빈 폴더는 다시 만듭니다) |
| 실행이 중간에 끊김(네트워크, 비정상 종료) | 다시 실행하세요. 페이지는 한 번만 만들어지고, 응답을 받지 못한 쓰기도 알아봅니다 |
| 서버가 노트 하나(편집 잠금, 읽기 전용 토큰)나 첨부 파일 하나(크기, 형식)를 거절함 | 그것만 건너뛰고 목록에 적습니다. 나머지는 동기화하고 실행은 종료 코드 0으로 끝납니다 |

브라우저에서 편집 중인 페이지도 안전합니다. 브라우저에서 아직 저장되지 않은 입력을 덮어쓰게 되는 볼트 업로드는 서버가 거절하고, 대신 둘을 합칩니다.

<a id="mapping"></a>
## 대응 관계

* 폴더 ⇄ 폴더 페이지. 하위 페이지가 있는 페이지는 `Page.md` + `Page/`가 됩니다(0.17부터 `X.md` 옆에 있는 `X/` 폴더는 언제나 X의 하위 페이지 폴더입니다).
* frontmatter ⇄ 페이지 속성: `tags`, `aliases`, 그리고 모든 `key: value`(텍스트, 숫자, true/false, `YYYY-MM-DD` 날짜, 목록). Inkling이 저장할 수 없는 frontmatter(중첩 맵, `key: |`, `updated`, 50개를 넘는 키)는 노트에 그대로 남고, 실행이 끝나면 목록에 나옵니다.
* `[[Wiki links]]` ⇄ 페이지 링크. 링크는 페이지 자체를 기준으로 이어지므로, 페이지 이름을 바꾸면 다른 노트에 있는 링크 글자도 바뀝니다(`[[New title|old text]]`). `[[Page#Heading]]`은 그 페이지의 해당 헤딩으로 가는 링크이고(페이지의 지금 제목으로 씁니다), 제목에 `#`가 들어간 페이지("C# notes")로 가는 링크도 동작합니다.
* 페이지 임베드, 인라인 데이터베이스 뷰, 링크 임베드, 플러그인 블록, 차트는 한 줄짜리 `<!-- inkling:… -->` 주석으로 씁니다(읽기 보기에서는 보이지 않습니다). 블록을 지우려면 그 줄을 지우세요.
* 이미지와 파일: Inkling에 저장하고, 볼트의 `assets/<id>.<ext>`에 똑같이 내려 둡니다. `![[photo.png]]` 임베드는 업로드한 뒤 표준 Markdown 이미지 링크로 바꿔 씁니다. 허용하는 형식은 png, jpg, gif, webp, avif, pdf, mp4, webm, mp3, m4a, wav, txt입니다. 글 줄 안에 들어 있던 이미지는 따로 한 줄로 옮겨집니다.
* ```` ```dataview ```` 블록은 그대로 두고, Inkling에서는 쿼리 블록으로 실행됩니다([QUERY.ko.md](QUERY.ko.md)).

<a id="known-losses"></a>
## 알려진 손실

처음 동기화할 때 노트를 Inkling의 Markdown 스타일로 다시 씁니다(`*` 글머리표, `*italic*`, 칸을 맞춘 표, 문단 안의 `\` 줄바꿈). 그 뒤로는 내용이 바뀔 때만 파일이 바뀝니다. 콜아웃 `> [!note]`(인용으로 보입니다), `![[Page]]` 페이지 임베드, `==highlight==`, `%%comments%%`, 수식, 인라인 필드 `key:: value`는 해석하지 않고 평범한 글로 남깁니다. 캔버스(`.canvas` 파일과 캔버스 페이지)와 컬렉션(데이터베이스) 페이지는 동기화하지 않습니다. 캔버스는 실행할 때마다 목록에 나옵니다. 컬렉션의 행은 필드 값 없이 평범한 노트로 동기화됩니다. 첨부 파일은 볼트에서 `assets/` 아래 파일을 고쳐도 업로드하지 않습니다.

손대지 않은 블록은 id가 그대로라서, 거기 달린 코멘트와 섹션 링크도 그대로 남습니다. 내가 고친 문단 안에 있던 멘션 칩이나 파일/오디오 블록은 `@Label`이나 링크로 바뀝니다. 최소한의 편집으로 반영할 수 없으면 페이지 전체를 다시 쓰고, 블록은 새 id를 받습니다(KNOWN-ISSUES SYNC-3). 표 칸 안의 이미지는 업로드할 때 빠집니다(VSYNC-3).

**0.16에서 올릴 때.** 0.16으로 마지막에 동기화한 노트는 처음 업로드할 때 새 형식(블록 토큰, 리비전 표시 `md2`)과 한 번 합쳐집니다. 이때 임베드 바로 옆 줄을 고쳤다면 충돌 사본이 하나 생기지만, 잃는 내용은 없습니다.

상태는 `<folder>/.inkling/`에 있습니다(`sync-state.json`, 합칠 때 쓰는 `base/` 사본, `trash/`). 이 폴더를 지우면 노트는 frontmatter의 `inkling-id`로 다시 연결됩니다. 이때 서버와 내용이 다른 노트는 충돌로 나옵니다. 합칠 기준이 되는 공통 버전이 없기 때문입니다.

실험 플래그를 없애기 전에 남은 일:

1. 동기화 읽기에 TAINT-1을 어떻게 할지 정합니다. `POST /sync/read`와 412, replay 본문에서 의심 표시 내용을 기록할지, 지금처럼 둘지, CLI만 예외로 둘지 고르고, 그와 함께 읽기 전용 토큰이 내려받기(pull)를 할 수 있게 할지도 정합니다(`POST /sync/read`는 지금 읽기 전용 토큰을 거절하고, 이것을 열면 제안만 토큰에도 열립니다). 기록하기로 하면, 의심스러운 줄이 하나라도 있는 워크스페이스에서는 토큰이 첫 동기화 직후 제안만 토큰이 됩니다.
2. 최소 편집이 안 될 때 쓰는 대체 경로(문서 전체 다시 쓰기)를 시험하고 거기서도 블록 id를 유지합니다. 아니면 대체 경로가 거절하고 대신 충돌 사본을 쓰게 합니다(SYNC-3).
3. 버전이 섞인 두 조합(0.17 CLI와 0.16 서버, 0.16 CLI와 0.17 서버)을 실제로 돌려 봅니다. 지금까지는 코드를 읽어서만 확인했습니다.
4. 동기화로 만든 페이지는 "새 페이지" 웹훅을 큐에 넣지 않고 `created_via`도 비워 둡니다(변경 피드에는 나옵니다, VSYNC-4).
5. 0.17의 동작 변경 여섯 가지를 리뷰에서 확인합니다(CHANGELOG, 0.17.0 Upgrade notes). 블록 토큰과 `md2` 표시, 폴더를 지우면 폴더 페이지도 휴지통으로 감(ADR 0202의 "folders are not deleted by sync", 곧 동기화로 폴더를 지우지 않는다는 결정을 뒤집음, ADR 2167), 낡은 리비전으로 보낸 `PUT`이 아무것도 바꾸지 않으면 200으로 답함, 만들기가 `clientKey`를 받고 재실행(replay)됨, 노트 하나에서 난 403은 건너뛰고 실행은 0으로 끝남, `X.md` 옆의 `X/`는 X의 하위 페이지 폴더임.
