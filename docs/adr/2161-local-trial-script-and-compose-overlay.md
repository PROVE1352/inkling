# 2161. A local trial in one command: deploy/local.sh and compose.local.yaml

- Status: Accepted
- Date: 2026-11-10

## Context
Trying Inkling on a laptop meant reading the server guide: copy `.env.example`, invent a database
password, start, issue a signup key, sign up. Things that commonly went wrong locally: port 3000 already
taken, the database port 55432 already taken (a second checkout, or another Postgres), `PUBLIC_URL` unset
(the MCP metadata and links then use the request host with a warning), `APP_SECRET_KEY` unset (a boot
warning, and no two-step verification), and `compose.yaml`'s fixed project name `nodian` (kept so existing
installs keep their volumes), which makes a second checkout on the same machine attach to the first one's
containers and volumes.

## Decision
- **`deploy/local.sh`** (`up` by default, `--build`, `stop`, `destroy`): checks Docker, then on the first
  run writes `.env` with a marker line, a hex `POSTGRES_PASSWORD` (hex because the password goes into a
  `postgres://` URL), an `APP_SECRET_KEY` (`openssl rand`, `/dev/urandom` without openssl),
  `PUBLIC_URL=http://localhost:<port>`, `COOKIE_SECURE=0`, `BACKUP_ENABLED=0`,
  `INKLING_PORT=127.0.0.1:<port>` (the first free of 3000, 3987, 3001–3010, or `INKLING_PORT` from the
  environment), `COMPOSE_FILE` and `COMPOSE_PROJECT_NAME`. It starts the stack, waits for `/api/health`,
  and prints the first-admin link (ADR 2160) only while `/auth/mode` says setup is pending, plus the MCP
  address and a `claude mcp add` line. A `.env` without the marker is never changed: the script stops and
  says why. `--build` sticks (a later plain run does not swap the published image in).
- **`compose.local.yaml`**: `name: inkling-local`, no host port for the database (`ports: !override []`,
  as the Caddy overlay does), the backup service behind a profile (no nightly dumps for a trial, and one
  image less to pull).
- **`compose.yaml`**: the two host ports become `${INKLING_PORT:-3000}` and
  `127.0.0.1:${INKLING_DB_PORT:-55432}`; with neither set nothing changes.
- **`APP_SECRET_KEY` is generated by the script, not by the server.** A server that made its own key would
  have to store it next to the data, and the data volume is in the backups, which ADR 1061 forbids for
  this key.
- The trial binds to 127.0.0.1 and uses http; a server other people reach still follows DEPLOY.md
  (Caddy, https, Secure cookies).

## Alternatives considered
- **A server-side "dev mode" that skips the key on localhost**: unsafe behind a proxy (ADR 2160).
- **Change compose.yaml's project name or ports**: breaks existing installs' volumes and scripts.
- **Copy `.env.example` and edit lines with sed**: `.env.example` is for development and servers (it sets
  `PORT=3001`, a dev `DATABASE_URL`); a short `.env` with only what the trial needs is easier to read and
  to recognise as the trial's.
- **`docker compose up --wait`**: waits for the app's healthcheck, whose 30 s interval makes the first
  start look slow; polling `/api/health` returns as soon as the server listens.
